# วงจร Origin และการตรวจโครงสร้าง

เจ้าของงาน Origin ยังคงรับผิดชอบงานเดิม มีพาธเนอร์อ่าน receipt จริงของงานนั้น
หากไม่มีคู่ที่ทำงานได้ Orchestration จะเป็นคู่สนับสนุนและบันทึกผลแทน
การส่งมอบนี้เกิดในรีโป้ ไม่ได้หมายถึงเรียกแชทบอทภายนอก

รอบตรวจของโมดูลที่มีพาธตรวจด้านโครงสร้างเรียก IGET ตรวจไฟล์ที่ประกาศไว้
และเรียก Orchestration ประสาน/เก็บวงจร พร้อมรายงานใน
`repo_events/origin_agents/<module>/collaboration/` และรายงานรอบตรวจเดิม

IGET ส่วนนี้อ่านข้อมูลจริง เก็บ hash และรายการฟังก์ชัน/การเรียกจาก Python AST
แต่ยังพิสูจน์วงจรข้ามระบบครบทั้งสายไม่ได้ จึงรายงาน `circuit_verification_required`
ไว้ให้ติดตาม ไม่สรุปว่าระบบสมบูรณ์เพียงเพราะ syntax ผ่าน
จุดค้างหรือข้อเสนอทำให้รอบตรวจเป็น 7 วัน; รอบที่ไม่มีสิ่งค้างยังใช้ 15 วัน

การซ่อมจากรอบตรวจต้องให้ BBX19 เลือกพาธจากรายงานก่อน ส่งผ่านช่องทางเจ้าของ
GitHub หรือ request ในรีโป้ที่เชื่อถือได้ ตัวอย่าง payload:

```json
{
  "structural_repair": true,
  "repair_selection": {
    "report_path": "repo_events/origin_agents/ChatGPT/collaboration/REPORT-review.json",
    "report_sha256": "hash ของรายงานที่ BBX19 พิจารณา",
    "paths": ["พาธที่เลือกจาก findings"]
  },
  "operations": [
    {"action": "edit", "path": "พาธที่เลือก", "old": "เดิม", "new": "ใหม่", "expected_sha256": "hash ไฟล์ปัจจุบัน"}
  ]
}
```

สิทธิซ่อมเป็นสิทธิชั่วคราวเฉพาะพาธที่เลือก ไม่เปลี่ยน IDP ถาวร
รายงานที่ถูกเปลี่ยนหลังพิจารณาหรือ operation ที่เกินพาธที่เลือกจะถูกปฏิเสธ
รายงานตรวจเสร็จไม่ใช่การซ่อมเสร็จ และไม่มีการซ่อมอัตโนมัติจาก findings
