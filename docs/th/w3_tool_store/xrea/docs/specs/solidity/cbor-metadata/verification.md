# การตรวจสอบ

ต้นฉบับ: [Verification](https://github.com/BBXDOO/W3_HB_team_BXCGICOG/blob/f22e21a587f69d4da8dccf30e653e2b45ce72c55/w3_tool_store/xrea/docs/specs/solidity/cbor-metadata/verification.md)

หลังผสาน upstream c462a4ebd การทดสอบ 47 รายการผ่าน ครอบคลุม parser, สัญญา domain, บริการ application, worker ที่คอมไพล์แล้ว และขอบเขต MCP (ห้าไฟล์)
golden ของ worker ที่คอมไพล์แล้วรวมข้อความ BOM ค่าซ้อนแบบ partial trailer ที่ unavailable UTF-8 ที่ผิดรูป และ float ที่ไม่รองรับ
การทดสอบ adapter ของ upstream อีกห้ารายการก็ผ่านหลังจากมีการตรวจสอบจำนวนเต็มที่เข้มงวดยิ่งขึ้น
งาน static ทั้งหกรายการและตัวป้องกันสถาปัตยกรรมผ่านทั้งหมด
หลังการผสาน การค้นหาการทดสอบพบทั้ง 1004 ไฟล์อย่างละหนึ่งครั้ง
การเลือกของ CI-planner ผ่านการทดสอบทั้ง 85 รายการ รวมถึงกรณี EVM-verifier ใหม่

การทดสอบ regression ของ parser ครอบคลุมจำนวนเต็มขนาดใหญ่และคีย์ที่ระบุชนิดอย่างแม่นยำ UTF-8 ที่ผิดรูป คีย์ซ้ำ การซ้อนลึกเกินไป tag/float ที่ไม่รองรับ ขอบเขตความยาว และการละไว้ในข้อมูลอดีต
ข้อบกพร่องจริงในการจัดการข้อความเริ่มต้นของ decoder ทำให้ U+FEFF ตัวแรกถูกลบ
tokenizer ที่เป็นเจ้าของขณะนี้ตรวจสอบและถอดรหัสไบต์ข้อความที่เก็บไว้โดยรักษา BOM; fixture อิสระตรวจสอบทั้งค่าและ identity ของคีย์ compiler

fixture ที่เป็นของโครงการคอมไพล์ด้วย solc 0.8.30 ที่ผู้เรียกเลือก โดยใช้การตั้งค่าแบบไม่ปรับให้เหมาะสม แบบปรับให้เหมาะสมผ่าน via-IR แบบไม่มี content hash และแบบไม่มี CBOR
การตรวจสอบ metadata ทั้งสี่ผ่านอีกครั้งหลังการผสาน ไม่มีการเรียกใช้ contract
การถอดรหัสครั้งแรกในเครื่องใช้เวลาประมาณ 0.81 ms หรือน้อยกว่า
ตัวเลขประมาณ 2.92 ms ที่รายงานเดิมสำหรับการทำซ้ำขณะอุ่นเครื่อง 100 ครั้งรวมการตรวจยืนยันความเท่ากัน จึงไม่ใช่การวัดเฉพาะการถอดรหัส
ขณะนี้ verifier วัดการแยกวิเคราะห์แยกจากการตรวจยืนยันเหล่านั้น แต่ยังไม่ได้เก็บเวลาขณะอุ่นเครื่องที่ปรับปรุงแล้ว
ตัวเลขในอดีตเหล่านี้อธิบาย fixture และ host นี้ ไม่ใช่ภาระงานทั่วไป
RSS สูงสุดของ process รวม compiler ด้วย (299536 KiB); ไม่ได้วัด CPU/หน่วยความจำของตระกูล process ทั้งหมดและต้นทุน token ของ agent

การทดสอบ worker ที่คอมไพล์แล้วใช้งาน EVMole WASM ที่ไม่ได้เปลี่ยนแปลงบน host macOS นี้
การทดสอบ MCP ใช้เซิร์ฟเวอร์และสัญญาที่ใช้งานจริงโดยมีจุดเชื่อมต่อ provider ที่ฉีดเข้ามา
ช่องทาง provider CLI/MCP ขีดจำกัดทรัพยากร และการล้างข้อมูลแบบครบถ้วนที่ใช้ได้เฉพาะ Linux ยังไม่ได้ตรวจสอบที่นี่
การผูก commitment ของ metadata JSON ยังคงเลื่อนไปภายใต้ issue #2388

verifier ของ Linux CLI/MCP ตรวจยืนยันไบต์ compiler ที่แน่นอน เวอร์ชันที่ประกาศ และช่วงของ candidate สำหรับ artifact แบบ raw/hex ที่เป็นของโครงการและมีอยู่เดิม
ช่องทาง CI ของมันยังรันเมทริกซ์การตั้งค่า compiler ใหม่ด้วย
การทดสอบ regression ที่ใช้ CI planner จริงตรวจสอบว่าการแก้ไข verifier ใหม่ทำให้เลือกช่องทาง EVM

การแก้ไขภายหลังจากการ merge/review เพิ่มความครอบคลุมของสรุปที่ถอดรหัสแล้วและ metadata ในอดีตที่ละไว้
การทดสอบและการรัน provider ซ้ำสำหรับการแก้ไขนั้นถูกข้ามตามคำขอของผู้ดูแล; การรันก่อนหน้าที่ระบุข้างต้นไม่ได้ตรวจสอบ head ที่เปลี่ยนแปลงแล้ว
