# แผนการนำไปใช้งาน

ต้นฉบับ: [Implementation plan](https://github.com/BBXDOO/W3_HB_team_BXCGICOG/blob/f22e21a587f69d4da8dccf30e653e2b45ce72c55/w3_tool_store/xrea/docs/specs/solidity/cbor-metadata/plan.md)

1. ใช้ cborg 6.1.3 (Apache-2.0) เป็นตัวถอดรหัสรูปแบบที่ตรึงเวอร์ชัน พร้อม tokenizer ที่จำกัดขอบเขต ณ ขอบเขต adapter ที่เป็นเจ้าของ ถอดรหัส map เป็น Map รักษาความแม่นยำของจำนวนเต็ม และตรวจสอบไบต์ข้อความที่ส่งออกอย่างเข้มงวดก่อนแปลง
2. เพิ่ม schema ผลลัพธ์ metadata แบบพกพาใน src/domain/evm/ ใช้ช่วงไบต์ที่แน่นอนภายใน bytecode ที่เก็บไว้แล้ว แทนการคัดลอก payload hex ของ CBOR ที่ไม่ตีความลงในทุกสรุปที่เลือก
3. เพิ่ม src/evm/SolidityMetadata.ts เพื่อตีความ candidate ของความยาวส่วนท้าย/root-map ส่งคืนข้อเท็จจริง unavailable, decoded, partial หรือ not-decoded โดยแสดงค่าซ้อนที่ไม่รองรับอย่างชัดเจนแทนการขยายแบบเรียกซ้ำ
4. คำนวณข้อเท็จจริงใน EvmoleInterfaceWorker จากไบต์ที่เลือก host provider ตรวจสอบช่วงและ identity แล้วส่งต่อฟิลด์ metadata ที่เพิ่มเข้ามา รักษาเอาต์พุตดิบของ engine โดยไม่เขียนทับ metadata ที่ไม่ทราบความแม่นยำ
5. ตรวจให้แน่ใจว่ารูปแบบ bytecode ของ EVM แบบ canonical ส่งฟิลด์ทางเลือกนี้ไปยัง Evidence ทั้งฉบับสมบูรณ์และสรุป รวมโปรไฟล์การถอดรหัส ความครอบคลุม และข้อจำกัด
6. เพิ่มการทดสอบความครอบคลุมของ producer, worker, สัญญาในอดีต และขอบเขต MCP สาธารณะ คอมไพล์ fixture Solidity ที่เป็นของโครงการด้วยโมดูล solc ที่ผู้เรียกส่งมาและตรึงเวอร์ชัน แล้วตรวจสอบเวอร์ชัน compiler ใน CBOR รันการตรวจสอบ static/สถาปัตยกรรมที่เกี่ยวข้อง
7. ขยาย verifier ของ Linux CLI/MCP จริงที่มีอยู่ด้วยการตรวจยืนยัน metadata แบบอิสระ รันเมทริกซ์การตั้งค่า compiler ในช่องทาง CI ของมัน และจัดประเภท verifier ว่าเป็นของ EVM พร้อมการทดสอบ regression ของ CI-planner ที่ใช้งานจริง

ไม่มีการเพิ่ม execution provider หรืออำนาจเหนือเป้าหมายใหม่: เพิ่ม parser ของรูปแบบภายใน worker EVM ที่มีอยู่
การรับเข้า provider บน Linux x64 ความหมายแบบไม่ต้องมีเป้าหมาย การล้างข้อมูล ขีดจำกัด และ Evidence ต้นฉบับฉบับสมบูรณ์ยังคงเดิม
ไม่มีการดึง metadata JSON หรือ URL ของซอร์สโดยอัตโนมัติ

parser จำกัดความลึกของการซ้อนที่ 64 และการเติบโตของ token/collection ตามจำนวนไบต์ของ payload ส่วนท้ายที่เลือก (ความยาวส่วนท้ายของรูปแบบมีค่าสูงสุด 65535)
ข้อมูลแต่ละรายการใช้ไบต์ที่เข้ารหัสไว้ ความยาว collection ที่ประกาศไว้มากเกินไปไม่สามารถใช้เป็นเหตุผลในการจัดสรรหน่วยความจำโดยไม่มีขอบเขตขั้นต่ำดังกล่าว
ผลลัพธ์ที่ขยายแล้วยังคงต้องผ่านการตรวจสอบเอาต์พุตขนาด 16 MiB ที่มีอยู่ของ worker
