# การตรวจสอบ metadata ส่วนท้ายของ Solidity

ต้นฉบับ: [Solidity terminal metadata inspection](https://github.com/BBXDOO/W3_HB_team_BXCGICOG/blob/f22e21a587f69d4da8dccf30e653e2b45ce72c55/w3_tool_store/xrea/docs/specs/solidity/cbor-metadata/spec.md)

Issue: https://github.com/morluto/rea/issues/2388

## ผลลัพธ์

การดำเนินการ EVM interface ที่มีอยู่ควรเก็บข้อเท็จจริงของ candidate CBOR ส่วนท้ายที่ถอดรหัสแยกต่างหากจากไบต์ที่เลือกอย่างตรงตัว แทนการพึ่งพาความแม่นยำที่ไม่ทราบของ metadata ที่ engine รายงาน
งานส่วนนี้ครอบคลุมช่วงของ trailer การถอดรหัสที่จำกัดขอบเขต หลักฐานคีย์จำนวนเต็ม/ค่าสเกลาร์ที่ไม่ใช่ข้อความอย่างแม่นยำ และรูปแบบการแทนเวอร์ชัน compiler

## ข้อกำหนด

- รักษา identity ของ carrier/ข้อมูลที่ถอดรหัสแล้วและ bytecode ต้นฉบับฉบับเต็มที่มีอยู่
- รายงาน candidate root-map ส่วนท้ายที่มีความเป็นไปได้แยกจากข้อพิสูจน์ว่ามีต้นกำเนิดจาก Solidity trailer ที่ขาดหายหรือไม่ใช่ map ยังคงเป็น unavailable ไม่ใช่การพิสูจน์ว่าไม่มี
- ตีความคีย์/ค่าแบบสเกลาร์ของ root-map โดยไม่สูญเสียข้อมูล: จำนวนเต็มเป็นสตริงฐานสิบ ไบต์เป็น hex รวมถึงสตริง บูลีน และ null เก็บค่าที่ยังไม่ได้ถอดรหัส/ไม่รองรับไว้ผ่าน bytecode ต้นฉบับพร้อม offset/length ที่แน่นอนของ candidate
- รายงานความครอบคลุมแบบ partial และ not-decoded ความล้มเหลวของ parser/profile และรูปแบบ CBOR ที่ไม่รองรับอย่างชัดเจน อย่าบังคับแปลงคีย์ที่ไม่รู้จักเป็น property ของ object โดยไม่แจ้ง
- ตีความรูปแบบ release/prerelease ของ solc ที่ยอมรับเฉพาะจากรายการที่สังเกตได้ รักษาความกำกวมเมื่อมีคีย์เวอร์ชัน compiler ซ้ำ
- ให้ฟิลด์ที่เพิ่มเข้ามาเข้ากันได้กับ Evidence ในอดีตและรักษาฟิลด์ไว้ในการส่งสรุปที่เลือกและ CLI/MCP สาธารณะ การละไว้ในข้อมูลอดีตจะถูกแยกวิเคราะห์เป็นแง่มุมที่ไม่ทราบค่าแบบ null โดยไม่แก้ไขต้นฉบับ
- จำกัดการซ้อนก่อน decoder เรียกซ้ำ และจำกัดความยาว collection ก่อนจัดสรรหน่วยความจำ ให้การแยกวิเคราะห์อยู่ภายใน worker ที่เป็นเจ้าของเดิมและงบประมาณทรัพยากร/เอาต์พุตของมัน
- ไม่ดึง metadata หรือเนื้อหาซอร์ส ไม่ติดต่อ RPC และไม่เรียกใช้โค้ด contract

## การยอมรับและขีดจำกัด

fixture ของ compiler ที่เป็นของโครงการและ trailer ที่ผิดรูป/สังเคราะห์ครอบคลุมจำนวนเต็มที่เกินความแม่นยำของ Number คีย์ที่ไม่ใช่ข้อความ ค่าซ้อน/ไม่ได้ตีความ UTF-8 ที่ไม่ถูกต้อง ความยาวที่ไม่ถูกต้อง tag ที่ไม่รองรับ และขอบเขตการซ้อน
การทดสอบขอบเขตสาธารณะรักษาฟิลด์และการละไว้ในข้อมูลเก่า
artifact ของ solc จริงที่ตรึงเวอร์ชันตรวจสอบข้อเท็จจริง metadata จริง โดยโปรไฟล์ host ของ EVM ที่จำกัดเฉพาะ Linux ยังคงเดิม

## เกณฑ์ของ issue ที่เลื่อนออกไป

การผูก metadata JSON ที่ส่งมากับ commitment ของ IPFS/Swarm เป็นงานส่วนเพิ่มแยกต่างหากในภายหลังของ #2388
PR นี้ต้องอ้างถึง issue แทนที่จะปิด issue ทั้งหมด
