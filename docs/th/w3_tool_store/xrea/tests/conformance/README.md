# ชุดข้อมูลทดสอบความสอดคล้องที่สร้างจากซอร์ส

ต้นฉบับ: [Source-built conformance fixtures](https://github.com/BBXDOO/W3_HB_team_BXCGICOG/blob/f22e21a587f69d4da8dccf30e653e2b45ce72c55/w3_tool_store/xrea/tests/conformance/README.md)

ซอร์สเหล่านี้ตั้งใจให้เป็นตัวอ้างอิงความถูกต้องเชิงความหมายขนาดเล็กสำหรับ provider ของ REA รัน
`npm run verify:fixtures` บน macOS หรือ Linux เพื่อคอมไพล์ลงในไดเรกทอรี
`build/conformance/` ที่ถูกละเว้น สร้าง manifest ของแฮชและชุดเครื่องมือ แล้วตรวจสอบ
สัญลักษณ์และสตริงตามรูปแบบดั้งเดิมของแต่ละแพลตฟอร์มด้วยเครื่องมือบรรทัดคำสั่งในเครื่อง
fixture แบบพกพาสำหรับ C, version และ large-inventory จะสร้างเป็น Mach-O บน macOS และ
ELF บน Linux ส่วน fixture สำหรับ Objective-C, Swift และแบบ N-API ยังใช้ได้เฉพาะ macOS

มีการจัดเก็บในระบบควบคุมเวอร์ชันเฉพาะไฟล์ซอร์ส ไบนารีที่สร้างขึ้น ซอร์สของ fixture
ขนาดใหญ่ที่สร้างขึ้น ข้อมูลดีบัก และ manifest ต้องอยู่ภายใต้ `build/` เท่านั้น

`ghidra/inventory.c` ยังถูกคอมไพล์เป็น ELF สำหรับ Linux แบบมีข้อมูลดีบักและแบบตัด
ข้อมูลออกชั่วคราวโดย `npm run verify:ghidra` ซอร์สนี้กำหนดฟังก์ชันภายใน การลิงก์
`puts` ภายนอก สตริงที่นิยามไว้ และหน่วยความจำที่เขียนและรันได้ ซึ่งจำเป็นต่อการพิสูจน์
ข้อกำหนด inventory แบบอ่านอย่างเดียวของ Ghidra โดยไม่ต้อง commit ไบนารี

`scripts/create-ghidra-windows-fixture.mjs` สร้างแอปพลิเคชัน PE แบบ native สำหรับ
x86-64 ที่ให้ผลลัพธ์แน่นอนและถูกละเว้นแยกต่างหาก สำหรับสายงาน Ghidra P0 บน Windows
ที่มีการควบคุม ตัวสร้างและค่า SHA-256 ที่กำหนดตายตัวถูกจัดเก็บในระบบควบคุมเวอร์ชัน
แต่ `.exe` จะไม่ถูก commit หรือรัน `npm run verify:ghidra:windows` ใช้ไฟล์นี้ตรวจสอบ
รายการปฏิบัติการแบบอ่านอย่างเดียวที่อนุญาต การเชื่อมโยง digest การรับส่งข้อมูล และ
การเก็บกวาด บน runner แบบ self-hosted ที่ใช้ Ghidra จริง

fixture C กำหนดลำดับการเรียกและสตริงที่ทราบแน่นอน คู่ fixture สำหรับเปรียบเทียบเวอร์ชัน
กำหนดสัญลักษณ์ที่เพิ่ม สตริงที่เปลี่ยน และความสัมพันธ์การเรียกที่เปลี่ยน ส่วน fixture
ขนาดใหญ่ที่สร้างขึ้นมีฟังก์ชันและสตริงที่ตั้งชื่อไม่ซ้ำกัน 1,205 รายการ เพื่อตรวจสอบว่า
provider ส่งคืน inventory ครบถ้วน fixture สำหรับ Objective-C, Swift และแบบ N-API
ให้ข้อมูลนำเข้าที่เน้น metadata โดยไม่ต้องพึ่งพาแพ็กเกจหรือเครือข่าย

`readiness/` เพิ่ม fixture สำหรับ JavaScript CLI และ Electron ที่สร้างจากซอร์สเท่านั้น
สำหรับตัวตรวจสอบความพร้อมในการสร้างกลับของ repository `npm run verify:readiness`
นำ fixture เหล่านี้มารวมกับ native fixture ที่คอมไพล์แล้ว ทดสอบความเท่าเทียมกันของ CLI
และ MCP สำหรับปฏิบัติการวิเคราะห์จริง และตรวจสอบรายงานภายในที่เครื่องอ่านได้ตามที่ระบุใน
`docs/reconstruction-readiness.md`
