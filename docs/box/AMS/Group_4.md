    ใน w3 นั้นได้มีการแยกกลุ่มเอกสารออกเป็น 4 ลักษณะใหญ่ๆ ดังหัวข้อใหญ่เอกสารนี้..
    
    BUILD : เอกสารที่มีแนวคิดในการ "สร้าง" นวัตกรรมใดๆ โดยมี ความแปลกใหม่ ,ริเริ่ม ,หรือพัฒนา มาจากแนวคิดใดๆ ก็ตาม ..มีรูปแบบ หรือลักษณะดังนี้..
    - มีโครงสร้าง
    - แนวคิด มีความชัดเจน 
    - มีขั้นตอน ,กระบวนการ
    - มีการกล่าวถึงที่มาและที่ไป
    - สามารถ ตรวจสอบได้ ในขั้นตอน หรือกระบวนการใดๆ
    - สามารถสร้าง เทส ,ทดสอบ ,ตัวอย่างการใข้งานได้
   เป็นต้น .
    
    ในภาพใหญ่นั้น มีความเหมาะสมที่จะใข้กับ เอกสารประเภท README หากมีการใช้ระดับ Folders tree และมี folder root อยู่ด้านนอกสุดหรือบนสุด.
    การนำรูปแบบ AMS มาผนวกกับ เอกสาร กลุ่ม BUILD นั้น เป็นการใช้รูปแบบอย่างมีนัยยะพอสมควร ..ในแง่ของบทบาท README ควรเป็นเอกสาร ที่ผู้ใช้ ต้องตั้งเป้าในการทำความเข้าใจ ระบบ หรือ โครงสร้างใดๆ เป็นอันดับแรกๆ  เพื่อเข้าใจว่า "ในพื้นที่ส่วนนี้" ประกอปไปด้วยอะไรบ้าง และมันมีหน้าที่อย่างไร 
    - ใช้ในการอ้างอิงได้  : README ไม่ควรนำเสนอเพียง เนื้อหา-สาระ แต่ยังต้องสามารถ อ้างอิงถึงความเกี่ยวพัน ที่มีกับส่วนอื่นๆได้ด้วย โดย นัยยะแรกนั้น คือการบอกว่า เนื้อหาหรือ ชุดข้อมูลใด ถูกนำไปใช้แล้ว ,ใช้ที่ใด ,กับอะไร เป็นการชี้ให้เห็นลักษณะการทำงานเชิงลึกว่า มีความเป็นไปได้มากน้อย แค่ไหนอย่างไร..
    อีกนัยนึงคือการ บอกกลายๆว่า สามารถตรวจสอบได้ ทั้งการสืบถึงต้นแบบ คอนเซบ หรือ การพัฒนา ,นำไปประยุกต์ใช้ในรูปแบบอื่นๆ เป็นต้น.
    
    ลักษณะโครงสร้าง ของ README นั้น จะมีรูปแบบการใช้งาน 2 ส่วนหลักๆคือ ขอบเขต และ พื้นที่การจัดสรรในเอกสาร.
    ขอบเขต ( BOUNDARY )
    - กำหนดใว้ให้เข้าใจตรงกันว่า ระดับรูท ของ Folder ทุกๆระดับ นั้น "จำเป็นต้องมี README อย่างน้อย 1 ชิ้นเสมอ" 
    - ใช้อธิบาย สิ่งที่อยู่ในระดับเดียวกับเอกสารนั้นๆ ( ENV )
    - ใช้สื่อสารว่า พื้นที่ส่วนนั้น เกี่ยวกับอะไร
    
    การจัดสรรภายในเอกสาร ( Internal allocation of documents )
    README มีรูปแบบการจัดสรร พื้นที่ภายในดังนี้
    
    1. Head line
    : ใช้ 4 บรรทัดแรก แสดง identity ของเอกสาร
    
    2. Body line
    : ใช้ บรรทัดที่5 ลงมาจนจบ เนื้อหาหรือ info ของเอกสาร.
    
    
    3. Movement line
    : ส่วนนี้ จะทำหน้าที่ระบุว่า ในระดับ folder ที่เอกสารนี้อยู่นั้น มีอะไรบ้าง แต่ละโฟลเดอร์ในนี้ คืออะไร รวมถึง ไฟล์ต่างๆ 
    : จากตรงนี้ยังสามารถเพิ่ม text link เพื่อสร้างทางลัดไปยังเอกสารที่เกี่ยวข้องได้
    
    
    4. OWNER ,MAKER
    : แสดงชื่อเจ้าของ และผู้จัดทำเอกสารนี้
    
    Boundary : AMS จะกำหนดให้ README  อธิบาย สภาพแวดล้อม ,พื้นที่ ,ระดับ Folder ที่มันอยู่เท่านั้น ยกเว้นการอ้างอิง.
    
    AM-TYPE : Ⅰ ,Ⅱ ,Ⅲ .
    ส่วนนี้คือ รูปแบบการระบุชนิด ของเนื้อหา และแตกต่างกันไปในแต่ละ Group เช่น Build
    AM Ⅰ - BUILD : ต้นแบบ ,คอนเซบ
    AM Ⅱ - BUILD : แนวคิดการประยุกต์ ,การออกแบบ
    AM Ⅲ - BUILD : Tests ,code

    OBSERVE : กลุ่มเอกสาร ที่เกี่ยวกับ เนื้อหาที่ยังไม่สมบูรณ์ หรือยังอยู่ในระยะการวางโครงสร้าง วางพื้นฐานแนวคิด หรือ รายงานการติดตามผลบางประเภทที่ต้องการ ข้อสรุปที่ชัดเจน ,แผนงาน ,ROADMAP ,การอธิบายลักษณะ /รูปแบบ ทริคเกอร์ ต่างๆในระบบ เป็นต้น.
    - เพื่อให้สามารถ แก้ไข ,ปรับปรุง ,ติดตาม ,ขยาย หรือปรับเปลี่ยน ได้ง่ายขึ้น และมีแนวทางที่ชัดเจน เอกสารเหล่านี้ "ไม่ใช่ README" เพราะมันคือ ส่วนที่ "อธิบายวิธีการทำงาน ,รูปแบบ ,ทิศทาง ,การตั้งเป้า หรือแม้กระทั่ง ลักษณะ ที่ผิดไปจากผลลัพธ์ที่คาดหวังใว้ว่าน่าจะเป็น

Learn : คือกลุ่มเอกสาร แนวปรัชญา ,แนวคิดหรือรูปแบบข้อปฎิบัติ ที่ใช้ยึดเหนี่ยวความคิดต่อสิ่งใด อย่างมีนัยยะ ,เอกสารความรู้ ,เนื้อหาเชิงลึก ,คู่มือ ,และ อื่นๆ ...
    เนื่องจากเป็นกรุ๊บที่มีขนาดใหญ่ที่สุด จึงต้องแยกโครงสร้างออกเป็น 
    - ประเภท
    - เนื้อหา
    - วัตถุประสงค์ของเนื้อหา
    - การใช้งาน และผลลัพธ์
    - ความสัมพันธ์
    ทั้งหมดนี้คือ ลักษณะ 5 ประการ โดยแต่ละลักษณะยังแบ่ง สาขาออกไปอีก โดยส่วนนี้จะกล่าวถึงในลักษณะที่ AMS สามารถใช้กับโครงสร้างได้ โดยยังคงให้ BOX ทำหน้าที่ กำหนดและ ขอบเขตความหมาย.
    
    ประเภท : ส่วนนี้คือการประกาศชัดว่า เอกสารอยู่ในหมวดไหน โดยจะขอกล่าวแบบกว้างและครอบคลุมก่อน  ..

    - ปรัชญา ,แนวคิด : LN4-
    - ทฤษฎีแนวทดลอง ,คอนเซบ ,ไอเดีย : LN5-
    - ประวัติ : LN6-
    - วิชาการ : LN7-
    - หมายเหตุ : LN8-
    - ศิลปะ ,การออกแบบ : LN9-
    - ข่าว ,ข้อมูล ,งานวิจัย : LNN-
    - สำหรับใช้กับโครงสร้างจองทุกกรุ๊ปใน AMS โดยตรง : LNM-

    เบื้องต้น AMS จะใช้ระบบสี ,สัญลักษณ์ ,อักษรย่อ เพื่อบอกสิ่งเหล่านี้ ได้แก่
