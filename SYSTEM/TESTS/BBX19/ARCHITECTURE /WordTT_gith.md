## คำศัพท์ Git และ Source Control

| ศัพท์/คำย่อ            | ความหมาย (ไทย)             | อธิบายเพิ่ม  |
|-------------------------|-----------------------------|--------------|
| repository (repo)       | คลังเก็บซอร์สโค้ด         | ที่เก็บโค้ดทั้งโปรเจกต์  |
| commit                  | การบันทึก (ชุด)โค้ด        | เปรียบเหมือน checkpoint  |
| branch                  | กิ่ง, สาขา                 | สำเนาโค้ดชุดหนึ่งสำหรับแก้ไขแยกต่างหาก |
| merge                   | รวมสาขา                    | รวมโค้ดจาก branch หนึ่งเข้ากับอีก branch |
| conflict                | ขัดแย้ง (กรณี merge)       | โค้ดชนกัน/เขียนไม่ตรงกันใน branch ต่างๆ |
| pull request (PR)       | คำขอขอให้ "รวมโค้ด"        | กระบวนการเสนอของใหม่เข้าหลัก (main) |
| fetch                   | ดึงข้อมูลจาก remote        | โหลดข้อมูลอย่างเดียว (แต่ไม่เปลี่ยนโค้ดในเครื่อง) |
| push                    | ส่งข้อมูลขึ้น remote        | อัปโหลดโค้ดจากเครื่องตัวเองขึ้น GitHub |
| clone                   | ก๊อป repo มาทั้งชุด        | ดึงทั้งประวัติ/โครงสร้างมาเครื่องตัวเอง |
| fork                    | ก๊อป repo ไปบัญชีตัวเอง     | ก๊อปแบบ “แยกออกไปเต็มตัว” |
| remote                  | ต้นทาง repo ที่อยู่ออนไลน์ | เช่น origin (GitHub) |
| upstream                | ต้นน้ำ, repo ต้นทางหลัก    | ปกติหมายถึง repo “ต้นฉบับ” |
| tag                     | ป้ายชื่อ (เวอร์ชัน)        | ใช้ mark code release เป็นต้น |
| diff                    | เปรียบเทียบโค้ด            | ดูว่าอะไรเปลี่ยน |
| log                     | ประวัติการแก้ไข            | รายการ commit ทั้งหมด |
| blob                    | ข้อมูลดิบไฟล์ใน git        | แสดงโค้ดของไฟล์นั้นใน git |

## ศัพท์ Blueprint, Template, Context, Plan, Agent

| ศัพท์/คำย่อ              | ความหมายไทย                          | อธิบายเพิ่ม                    |
|--------------------------|---------------------------------------|-------------------------------|
| agent                    | ตัวแทนอัตโนมัติ, โมดูลย่อย           | ส่วนย่อยที่ “ทำงาน” เฉพาะทาง  |
| blueprint (bp)           | ต้นร่าง, แบบฟอร์ม, แม่แบบ             | ใช้ define โครงสร้าง output   |
| template                 | เทมเพลต, ฟอร์ม                       | ข้อมูลต้นฉบับที่ให้เติมข้อมูล |
| plan                     | แผนงาน/แผนดำเนินการ                   | โครงสร้างบอกว่าต้องการอะไร   |
| context                  | บริบท                                 | ข้อมูลประกอบ เช่น ผู้ใช้, สถานที่, เวลา |
| doc, document            | เอกสาร (input, ข้อมูลจากไฟล์)         | .txt, .pdf, .md ฯลฯ           |
| save_path                | ที่เก็บไฟล์ผลลัพธ์                    | path=outputs/summary.md       |
| orchestrate, orchestrator| ประสานงาน, ชุดประสาน agent หลายตัว    | Flow control หลัก             |
| responsibilities         | ความรับผิดชอบ                         | งานที่ agent ต้องรับผิดชอบ    |
| run                      | เรียกทำงาน (เมธอด/ฟังก์ชัน)           | agent.run(...)                |
| output                   | ผลลัพธ์, สิ่งที่สร้างขึ้น              | อาจเป็นไฟล์/ข้อความ           |

## ศัพท์ CLI / Python / Workflow

| ศัพท์/คำย่อ          | ความหมายไทย                 | ตัวอย่าง/อธิบาย                       |
|----------------------|-----------------------------|----------------------------------------|
| argument, param      | อาร์กิวเมนต์, พารามิเตอร์ | ข้อมูลที่ใส่ผ่าน CLI/ฟังก์ชัน         |
| parse, parser        | การแปลง สกัดแยกข้อมูล     | argparser, json parser                 |
| instance, instantiate| อินสแตนซ์, การสร้างอ็อบเจกต์ | agent = MyAgent()                    |
| method, function     | เมธอด, ฟังก์ชัน             | def run(...):, agent.run(...)         |
| return               | คืนค่า                        | return output                         |
| map, mapping         | แมป, การจับคู่/ผูกข้อมูล     | mapping field ระหว่าง plan/context    |
| list, array          | รายการ, อาเรย์               | [1,2,3], ['a','b']                    |
| dictionary, dict     | ดิกชันนารี, คีย์-ค่า         | {"name": "BBXDOO"}                    |

## เทคนิคอ่านศัพท์ (How to decode the jargon)
- คำว่า run, plan, template ส่วนใหญ่ตรงตัว หรือเป็น function/action/โครงสร้าง
- agent คือ ตัวที่ทำงานเอง (มนุษย์อ่านเสมือน robot ช่วยงาน)
- blueprint = template “แบบเป็นทางการ/ที่กำหนด/รีวิวได้”
- context = สิ่งที่เติมสีสันในการสนทนา เช่น “ผู้ใช้, ปม, ใคร, เมื่อไร”
- orchestrate/orchestrator = ตัวแม่ Flow/ผู้ควบคุมซิมโฟนีทั้งหมด
