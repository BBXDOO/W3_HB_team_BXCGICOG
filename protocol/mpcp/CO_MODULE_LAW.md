# CO_MODULE_LAW.md

MPCP Cooperative Module Paper — Request / Assist / Cross Field Culture

Status: ACTIVE DRAFT  
Owner: BBX19  
Scope: cooperative module culture / Cross-X assist / Paper Pack flow / event trace

---

## 1. Purpose

W3 systems should not be designed as lonely modules.

A module may hold responsibility, but it should not be forced to perform every method alone.

```text
A = responsible module
B = assisting module
C = shared cross field / agreement point
```

The goal is not to make one module stronger than all others.
The goal is to let modules request, assist, coordinate, and return trace.

---

## 2. Culture law

```text
Request before control
Assist before replacement
Coordinate before execution
Trace before conclusion
```

A module may ask another module for help without losing responsibility.
A helper module may support without taking over authority.

No module should assume:

```text
I must do all work alone.
I must replace the other module.
I must own the whole result.
```

---

## 3. A / B / C relation

```text
A = responsible module
B = assist module
C = cross field
```

A carries responsibility.
B contributes capability.
C keeps the relation visible and traceable.

C may be:

```text
Cross-X
Table-X
Paper Pack
Event field
Trace field
Result tag layer
```

C is not always a third module.
C may be the temporary shared field where two flows meet.

---

## 4. Cross-assist law

A tag may point to a responsible module, but it does not forbid another module from assisting.

Example:

```text
A result is tagged as MPCP-related.
MPCP remains responsible.
But W3Lgu / Table-X may be easier, faster, and clearer for relation work.
MPCP may use Cross-X to call that field for assistance.
The trace returns to MPCP.
```

Rule:

```text
Responsibility is not monopoly.
Assistance is not authority theft.
Crossing field is not system escape.
```

---

## 5. Direction can change

A work path may change direction when the field shows a better path.

```text
A line may meet another line.
The crossing point may create temporary agreement.
The work may expand.
The work may shift field.
The work must keep trace.
```

Changing field is valid when:

```text
boundary remains visible
responsibility remains traceable
result returns to the responsible module
no source truth is hidden
no execution authority is invented
```

---

## 6. Cooperative contract

A cooperative module contract should carry:

```text
RESPONSIBLE_MODULE
ASSIST_MODULES
CROSS_FIELD
REASON
RETURN_TO
EVENT_ID
END_EVENT
PAPERS
TRACE
```

Optional markers:

```text
ROT_TYPE
PAPER_PACK_ID
FIELD_SELECTED
TEMP_AGREEMENT
CAN_CHANGE_DIRECTION
CAN_EXPAND
ENV_REF
STACK_REF
LRC_REF
```

## 7. Paper Pack flow example

```text
EVENT-A01 : #MPCP/LIB'Blueprint
REDR/ROT  : Papers-Pack / Cross-X

Paper-A01.1 : Table-X'PX ; _MPCP/ACE
Paper-A01.2 : file.void ; _MPCP/ACE
Paper-A01.3 : Modew-dynamic E-A01.3
Paper-A01.4 : Modew-dynamic E-A01.4

Cross-X : END
MPCP/Lib'Blueprint : Combine the results
LRC2 : LOG
End Event : 1
```

Note:

```text
End Event is the terminal marker of the flow.
In this example it is 1, not A01.
A01 is the event identity.
1 is the end marker / completed flow point.
```

---

## 8. Fail / stop condition

The cooperative relation is invalid when:

```text
A loses responsibility
B takes authority without Paper
C hides the trace
field changes without reason
result does not return to RETURN_TO
source truth is mutated without permission
```

---

## 9. Final law

```text
No module works alone.
No helper steals the work.
No cross field hides the truth.
Every assist returns trace.
```
