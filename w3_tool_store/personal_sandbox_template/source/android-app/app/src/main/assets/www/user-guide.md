# คู่มือ W3 Personal Sandbox — v52 (0.52)

<!-- manual-version: 52 -->
<!-- reviewed-version: 52 -->

ปรับตามเมนูและโค้ดรุ่น v52 เมื่อ 5 พฤศจิกายน 2026 คู่มือเดียวกันนี้บรรจุใน APK และอ่านได้ในกิท เลขนี้เป็นรุ่นคู่มือ/แอป แยกจากเวอร์ชันโครงการที่ผู้ใช้ตั้งเอง

เปิดจาก **? คู่มือ** ด้านบน หรือ **คำสั่งและคู่มือ → คู่มือ** ด้านล่าง พิมพ์ชื่อเมนูในช่องค้นหาเพื่ออ่านเฉพาะหัวข้อที่เกี่ยวข้อง เลื่อนขึ้นลงเพื่ออ่าน ตารางและบล็อกโค้ดที่กว้างเลื่อนแนวนอนได้

## คลังโครงการ: สร้าง เปิด นำเข้า และสำรอง
<!-- menu: library -->

หน้าเปิดแอปแสดงคลังโครงการ การ์ดแสดงชื่อ รูป ID เวอร์ชัน ผู้จัดทำ สถานะ ความคืบหน้า และจำนวนรายการตามข้อมูลที่มี แตะการ์ดหรือ **เปิดโครงการ ↗** เพื่อเข้าโครงการ

| ปุ่ม / ตัวเลือก | วิธีใช้และผล |
| --- | --- |
| + INITIALIZE NEW CORE / Add Memory Block | กรอกชื่อ เลือกประเภท แล้วกดสร้าง |
| Library | ประเภทเริ่มต้นสำหรับเอกสาร คู่มือ และเรื่องเล่า |
| BG – Bookcraft | ประเภทเริ่มต้นสำหรับเกม บอร์ด และการ์ด |
| Concept mind map | ประเภทเริ่มต้นสำหรับข้อมูลและความสัมพันธ์ |
| นำเข้า JSON | เลือกไฟล์สำรอง ถ้า ID ซ้ำจะถามก่อนแทนที่โครงการและจุดเล่น |
| วิธีสำรองและติดตั้ง | เปิดคำอธิบายการสำรองและการติดตั้ง |
| ✕ บนการ์ด | ลบโครงการหลังยืนยัน ควรสำรองก่อนลบ |

แต่ละโครงการมีข้อมูลแยกกัน ประเภทช่วยจัดรายการใช้งานเริ่มต้น ยังใช้หน้าแก้ไขอื่นร่วมกันได้ Chrome กับ APK เก็บข้อมูลคนละพื้นที่ ให้ใช้ JSON เพื่อย้ายข้อมูล

ตัวอย่างเริ่มงาน: สร้างโครงการ → ตั้งชื่อ → Library → เรื่องราว → เพิ่มตอน → บันทึก → ส่งออก JSON

## เรื่องราว: Story และตัวเขียนเต็มจอ
<!-- menu: story -->

แผงรายการใช้ค้นหา เลือก เพิ่มตอน และนำเข้าเอกสาร ตอนมี **Passage Label** ชื่อ, **Narrative Payload** เนื้อหา และ **Decision Logic** ตัวเลือกไปตอนอื่น ด้านล่างเป็นพรีวิว

1. เปิด **รายการ / เพิ่ม** แตะตอนหรือ **เขียนตอนใหม่** เพื่อเปิดตัวเขียนเต็มจอ
2. ตั้งชื่อและเขียนต้นฉบับ เลือก **เขียน / เขียน + พรีวิว / พรีวิว**
3. เลือก **Markdown / GitHub** สำหรับเอกสารใหม่ หรือ **ข้อความเดิม** สำหรับตอนเก่า
4. แถบคำสั่งมีหัวข้อ ตัวหนา เอียง ขีดฆ่า รายการ เช็กลิสต์ ตาราง ลิงก์ และบล็อกโค้ด ปัดแนวนอนเพื่อดูปุ่มอื่น
5. **↶ / ↷** เลิกทำ/ทำซ้ำ, **A− / A+** ปรับขนาดในตัวเขียนและพรีวิว, ค้นหา/แทนที่ใช้ข้อความตรงตัวตามช่องค้นหา
6. กดบันทึกหรือรอหลังหยุดแก้ประมาณ 2 วินาที ดูผลที่แถบล่าง หากบันทึกไม่ผ่านให้ส่งออกก่อนปิด
7. **← Story** หรือย้อนกลับ Android กลับรายการตอน

**นำเข้าไฟล์** รองรับ .md, .markdown, .txt แบบ UTF-8 ไม่เกิน 4 MB เลือกสร้างตอนใหม่ เพิ่มท้าย หรือแทนที่ตอนปัจจุบัน การแทนที่มีคำยืนยัน **ส่งออก .md / .txt** ส่งออกต้นฉบับเฉพาะตอน ส่วนสำรองทั้งโครงการใช้ JSON บนแถบหลัก

พรีวิวรองรับ Markdown รวมตารางและส่วนพับ `<details><summary>หัวข้อ</summary>…</details>` ภาพภายนอกแสดงคำบรรยายแทน ลิงก์เว็บไซต์เปิดเมื่อแตะ

ใน Decision Logic เพิ่ม **Player Choice** เป็นข้อความปุ่ม แล้วเลือก **Redirect to** เป็นตอนปลายทาง ทดลองกดในเมนูทดลอง หากปลายทางหายจะแจ้งปัญหา ตัวเลือกนี้ไม่ได้ประเมินเงื่อนไขเกมอัตโนมัติ

## ตัวละคร: Characters
<!-- menu: character -->

เพิ่มหรือเลือกตัวละครจากรายการ แก้ข้อมูลด้านขวาและดูพรีวิวด้านล่าง

| ส่วน | วิธีใช้ |
| --- | --- |
| Name / Role | ชื่อและบทบาท เช่น ผู้เล่น NPC หรือศัตรู |
| ภาพตัวละคร | เลือกภาพจากเครื่อง ใช้ในพรีวิวและ Battle |
| HP / MP / EN | ค่าพื้นฐาน ค่าในรอบเล่นอาจเปลี่ยนแยกจากต้นฉบับ |
| Logic Modules A / B / C | เลือกการ์ดจากโครงการมาอ้างในแต่ละช่อง |
| Output Preview | ข้อความผลสรุปประกอบตัวละคร |
| Elements & History | กลุ่มธาตุ ความสามารถติดตัว และ Biography |
| Capabilities Matrix | ค่าตาม schema ของโครงการ |
| ACT / DEF / SPE / CRI | คุณลักษณะที่ Battle ใช้ได้ตามสูตรที่ตั้ง |
| ช่องความสามารถ | ตั้งชื่อช่องและเลือกการ์ดที่ติดตั้ง |
| จัดการคุณลักษณะ | เพิ่ม/แก้ KEY, NAME และค่าเริ่มต้น |

ใช้ KEY สม่ำเสมอ เช่น INT เพื่ออ้างจากกฎ บทบาทและประวัติเป็นข้อมูลที่กำหนด การตั้ง Role เป็น NPC ไม่ได้สร้างพฤติกรรม NPC อัตโนมัติ

## การ์ดและโมดูล: Cards / Modules
<!-- menu: card -->

มีแท็บ **การ์ด** กับ **โมดูล** พร้อมค้นหารายการ

**โมดูล:** เพิ่มแล้วตั้งชื่อ ประเภท Grade รายละเอียด และข้อความ **A / B / C** การ์ดหยิบโมดูลไปประกอบได้ ส่วนการเชื่อม Battle ระบุ SKILL/PASSIVE/CORE, Rules สำหรับเปิดผลเสริม และผล HP/MP/EN หรือเพิ่ม/ถอดสถานะตนเอง/อีกฝ่าย

**การ์ด:** ตั้ง Module Name, Type (SKILL/PASSIVE/CORE), Grade, Access (A/B/C/ALL), Rarity และคำอธิบาย เลือกจำนวนช่องประกอบ 2 หรือ 3 แล้วเลือกโมดูลในแต่ละช่อง ถอดด้วยรายการว่าง ส่วน Input / Rule, Logic Process และ Output / Final Effects เก็บข้อความเดิมของการ์ด ค่าใช้จ่ายและ cooldown แก้ตามช่องในหน้า พรีวิวแสดงข้อมูลและโมดูลที่ประกอบ

ในเมนูทดลอง เลือกการ์ดแล้วกด **ลองเดินโฟลว A → B → C** ระบบอ่านโมดูลตามลำดับช่องและส่วนที่ไม่ว่าง รองรับ `PASS` กับ `DISPLAY: ข้อความ` ข้อความอื่นคืน UNKNOWN, โมดูลหายหรือ DISPLAY ว่างคืน ERROR โฟลวนี้ไม่รันโค้ดทั่วไป ไม่เปลี่ยนค่าสถานะ และยังไม่บังคับ Grade/Access การเชื่อม Battle ใช้ตัวประมวลผลของ Battle ตามหัวข้อถัดไป

## บอร์ด: ตารางและพื้นที่ข้อมูล
<!-- menu: board -->

ด้านซ้ายกด **สร้างพื้นที่อาณาจักรใหม่** หรือเลือกบอร์ดเดิม แก้ **ชื่อพื้นที่/อาณาจักร**, **Width (Cells)**, **Height (Cells)** แล้วกด **อัปเดตขนาดตาราง** ขนาดแต่ละด้าน 1–50 ช่อง พิกัดเริ่ม 0,0 การลดขนาดซ่อนข้อมูลนอกขอบเขตแต่ยังเก็บใน cellMap จึงอาจปรากฏอีกเมื่อขยายกลับ ควรสำรองก่อนปรับ

พรีวิว BOARD WORKSPACE มีสี่มุมมอง อ่านข้อมูลชุดเดียวกัน:

| มุมมอง | ทำอะไรได้ |
| --- | --- |
| ภาพรวม | แผ่นข้อมูลสี แตะเลือก ดูจำนวนและสัดส่วนประเภท |
| ตารางพิกัด | แตะช่อง ปรับขนาด รูปช่อง พิกัด และธีมตาราง |
| ฐานข้อมูล | รายการพร้อมพิกัด ค้นชื่อ/รายละเอียด เรียงพิกัดหรือชื่อ |
| มายด์แมพ | ทรีหัวข้อหลัก/ย่อย เพิ่มใต้หัวข้อที่เลือกหรือเปลี่ยนแม่ |

### แก้ข้อมูลช่อง

เลือกช่องแล้วแก้ด้านขวาหรือเปิด **รายละเอียด / เครื่องมือ**:

- **Entity Type:** Empty, Location Hub, Encounter Point, Neutral Zone เป็นประเภทข้อมูลช่อง
- **Display Label / ชื่อ:** ชื่อเรียกพิกัด
- **Atmospheric Log / รายละเอียด:** ข้อความประกอบ
- **Visual Skin:** เปิดหน้าต่างเลือกไอคอน สีสำเร็จรูป หรือสีเอง กดยืนยันจึงใช้
- **สีช่อง / ไอคอน:** แก้โดยตรงจากรายละเอียดในพรีวิว
- **เพิ่มรายการ:** ใช้ช่องว่างแรกที่ยังไม่มีข้อมูล หากเต็มต้องขยายบอร์ด
- **เพิ่มหัวข้อย่อย / เชื่อมจากหัวข้อแม่:** ใช้ในมายด์แมพ
- **ลบรายการนี้:** ล้างข้อมูลช่องหลังยืนยัน ลูกของหัวข้อนั้นจะถูกปลดความสัมพันธ์
- **ลบพื้นที่นี้:** ลบบอร์ดทั้งใบหลังยืนยัน

Location เป็นข้อมูลแยกอีกเมนู การเลือกชนิด Location ไม่ได้สร้างสถานที่ให้อัตโนมัติ พิกัดนี้ไม่ใช่ GPS

### ขนาดและธีมเฉพาะตาราง — v52

ในตารางพิกัดเลือก **ช่องมน / จุด**, **พอดีจอ**, เปิด **พิกัด** และเลื่อน **ขนาด 8–64 px** ตารางที่กว้างเกินจอเลื่อนดูได้ พอดีจอคำนวณขนาดจากพื้นที่ปัจจุบัน

เปิด **🎨 ธีมเฉพาะตาราง** ใต้แถบขนาด:
1. เลือกชุด **ดำเทา / กระดาษ / เขียวป่า / น้ำเงิน** เพื่อเห็นผลทันที
2. ปรับสีเองได้ห้าส่วน: **พื้นตาราง / ช่องว่าง / เส้นตาราง / ตัวอักษร / กรอบช่องที่เลือก**
3. เลือกสีที่อ่านชัด กด **บันทึก** บนแถบหลักเพื่อเก็บกับบอร์ดนี้
4. **คืนค่าเริ่มต้น** กลับชุดดำเทา
5. ส่งออก JSON เก็บธีมไปกับบอร์ด เปิดใหม่/นำเข้าก็ใช้ค่าเดิม

มีผลเฉพาะมุมมองตารางพิกัดของบอร์ดที่เลือก เมนูแอป บอร์ดอื่น ภาพรวม ฐานข้อมูล มายด์แมพ และตารางหน้าเล่นใช้การแสดงผลเดิม สีเฉพาะช่องยังแสดงทับสีช่องว่างตามเดิม

## สถานที่: Locations
<!-- menu: location -->

กด **+ NEW SECTOR** เลือกสถานที่ แล้วแก้แผงข้อมูล พรีวิวแสดงตามที่กรอก

| ช่อง / ส่วน | ความหมาย |
| --- | --- |
| Label / Zone | ชื่อและเขต |
| Archetype | Indoor / Outdoor / Dungeon / City |
| Threat | ระดับภัยคุกคามเป็นตัวเลข |
| Clearance | Public / Restricted |
| Temporal | Any / Day / Night |
| Overview | คำบรรยาย |
| Active Triggers | เพิ่ม/แก้เงื่อนไขและข้อมูลการอ้างอิง |
| Loot Distribution | ไอเทมที่อ้าง โอกาส % และจำนวน Qty |
| PURGE / ลบ | ลบระเบียนที่เลือก |

Trigger และ Loot เป็นข้อมูลกำหนด ยังไม่แจกของหรือเปลี่ยนฉากอัตโนมัติ การดูสถานที่จากบอร์ดต้องมีรหัสอ้างอิงอยู่ในข้อมูลช่อง

## ไอเทม: Items
<!-- menu: item -->

กด **+ NEW ASSET** เลือกไอเทม แล้วแก้ข้อมูล:

| ส่วน | รายละเอียด |
| --- | --- |
| Label / Asset ID | ชื่อและรหัสแสดง ระบบมี ID ภายในสำหรับเชื่อม |
| Type | Consumable / Key Item / Weapon / Material |
| Rarity | Common / Rare / Epic / Legendary |
| Properties | Stackable อนุญาตให้ซ้อน, Max Stack จำนวนสูงสุด, Weight น้ำหนัก, Description |
| Usage Logic | Instant / Equip / Passive, Cooldown (Turns), Consume on use |
| Effects | ADD EFFECT เพิ่มแถว Condition / Effect / Target, ✕ ลบแถว |
| PURGE | ลบไอเทมจากทะเบียน |

ในทดลองเปิด Items กด **หยิบ +1 / นำออก −1** เพื่อปรับกระเป๋าตัวละครที่เลือกหรือกระเป๋าโครงการ ระบบตรวจทะเบียน จำนวนติดลบ และ Stackable/Max Stack กดบันทึกจุดอ่านเพื่อเก็บจำนวน Effects ทั่วไปยังไม่ถูกนำไปใช้ไอเทมอัตโนมัติ

## เหตุการณ์: Events
<!-- menu: event -->

เพิ่มและเลือกอีเวนต์ ตั้งชื่อและ **Execution Type** (Special / Random / Story/Main) จากนั้นกำหนด:

| ส่วน | หน้าที่ |
| --- | --- |
| Trigger / When | เหตุเริ่ม เช่น OnInteract |
| Condition | เช่น HP >= 50 |
| Priority / Cooldown | ลำดับและระยะพักที่บันทึก |
| Rule of Area | ข้อความกฎพื้นที่ |
| Spatial Anchor | Target Board, Coordinate X / Y |
| Workflow Pipeline | เพิ่มขั้น Process / Target / Data/Log |
| Outcomes | IF เงื่อนไข, THEN เช่น +HP 10 |
| Monitor | พรีวิวข้อมูลที่ตั้ง |

กดโต้ตอบในทดลองเพื่อรันส่วนที่รองรับ: OnInteract, cooldown 0, เงื่อนไขตัวเลข HP/MP/EN, Message ไป Self และผลปรับ HP/MP/EN ตามตัวประมวลผล คำสั่งที่ไม่รองรับจะหยุดโดยไม่ใช้ผลบางส่วน ชื่อ Random หรือ Process ที่กรอกไม่ได้สร้างตัวรันขึ้นเอง

## กฎ: Rules
<!-- menu: rule -->

ซ้ายกด **+ NEW RULESET** เลือกชุดกฎ ขวาตั้งชื่อ เพิ่มข้อหลัก/ข้อย่อย แต่ละข้อมี:
- ชื่อและเนื้อหา
- ประเภท **คำอธิบาย/อ้างอิง** สำหรับอ่าน หรือ **เงื่อนไขที่นิยามไว้** สำหรับตรวจ
- ชื่อ input เช่น character.INT
- ตัวเปรียบเทียบ exists / == / != / > / >= / < / <=
- ค่าที่เทียบ ยกเว้น exists
- อ้างอิง ID คำสั่ง Common Play หากต้องการ
- เพิ่มข้อย่อยหรือลบข้อ การลบแม่ลบแขนงย่อยด้วย

ด้านล่างเป็น Rule Tree Preview ส่วน **ทดลองตรวจบริบท** รับ JSON object แล้วกด **ตรวจเงื่อนไข** เช่น:
```json
{"area":{"type":"เมือง"},"character":{"INT":4}}
```
ตั้ง input character.INT, >, ค่า 3 เพื่อทดลอง ดู PASS / FAIL / UNKNOWN / ERROR และเหตุผลแต่ละข้อ บริบทนี้ไม่บันทึกเข้าโครงการ ข้อย่อยตรวจแยก ไม่สืบทอดเงื่อนไขแม่อัตโนมัติ

ในทดลอง กด **ตรวจ Rules กับบริบทปัจจุบัน** เพื่ออ่านข้อมูลที่เลือก เช่น board.width, cell.x, character.INT, character.hp เปิดข้อมูลที่ส่งเข้ากฎเพื่อตรวจได้ การตรวจทั่วไปไม่เปลี่ยนสถานะหรือเรียก Common Play ส่วน Rules ที่ผูก Battle ใช้ตามเงื่อนไข Battle

## คำสั่ง: Common Play
<!-- menu: commonPlay -->

เก็บทะเบียนคำสั่งเฉพาะโครงการ เพิ่มรายการ ตั้งชื่อ คำอธิบาย และ input ที่ต้องมีคั่นจุลภาค กดออกจากช่อง input เพื่อยืนยันค่า แต่ละรายการมี ID ถาวร คัดไปอ้างในข้อกฎได้ เปลี่ยนชื่อแสดงได้โดย ID เดิม

ข้อกฎผ่านแต่อ้าง ID ที่ไม่มีคืน ERROR มีคำสั่งแต่ไม่มีตัวประมวลผลหรือ input ขาดคืน UNKNOWN การเขียนคำอธิบายไม่ได้สร้างโปรแกรม รายการรวมอยู่ในสำรอง JSON ของโครงการ

## ทดลอง: Playtest และจุดอ่าน
<!-- menu: play -->

ส่วนบนเป็นเครื่องมือรอบเล่น เมนูซ้ายหรือแถบแนวนอนเลือกรายการ พื้นที่หลักแสดงเนื้อหา เมนูต่างกันได้ตามประเภทและการตั้งค่าโครงการ

| เครื่องมือ | ผล |
| --- | --- |
| บันทึกจุดอ่าน | เก็บตำแหน่งอ่าน ตัวละคร ตำแหน่งบอร์ด ค่ารอบเล่น กระเป๋า ลูกเต๋า และ Battle ที่รองรับ |
| เปิดจุดอ่าน | โหลดสถานะที่บันทึกกลับ |
| เริ่มใหม่ | รีเซ็ตรอบเล่นตามคำยืนยัน ไม่ลบต้นฉบับ |
| ลูกเต๋า | d4/d6/d8/d10/d12/d20/d100 จำนวน 1–10 ลูก ประวัติ 20 รายการเมื่อบันทึกจุดอ่าน |
| ตั้งค่าหน้าใช้งาน | เพิ่ม/ลบเมนู เปลี่ยนชื่อ ไอคอน ลำดับ แสดง/ซ่อน และพื้นหลัง |

ลบรายการเมนูหน้าใช้งานยังเก็บต้นฉบับไว้ การโต้ตอบ:
- เรื่อง: อ่านและกดตัวเลือกไปตอนอื่น
- บอร์ด: แตะช่องเพื่อดู เลือกตัวละครแล้วกดวาง/ย้ายจึงเปลี่ยนตำแหน่ง กรอบช่องเลือกกับจุดตำแหน่งตัวละครเป็นคนละสถานะ
- สถานที่/เหตุการณ์: อ่านข้อมูลอ้างและโต้ตอบ Event ที่รองรับ
- ตัวละคร: ดูข้อมูลและค่ารอบเล่น
- การ์ด: ทดลองโฟลวโมดูล
- ไอเทม: หยิบ/นำออกจากกระเป๋า
- กฎ: ตรวจบริบทปัจจุบัน
- Battle: เล่นตามกติกาที่กำหนดด้านล่าง

ก่อนสำรอง ให้บันทึกจุดอ่าน → บันทึกโครงการ → ส่งออก JSON การเปลี่ยนรอบเล่นที่ยังไม่บันทึกจุดอ่านจะไม่อยู่ในสำเนา

## ทดลอง: Battle และโมดูล
<!-- menu: battle -->

เปิด **Battle** ถ้าไม่มี ให้ตั้งค่าหน้าใช้งานแล้วเพิ่ม Battle เริ่มจากกติกาของโครงการเอง

**ตั้งค่าสนามและคำสั่ง / เริ่มกำหนด:**
1. เลือกพื้นที่จาก Locations หรือไม่ผูก
2. กรอกชื่อสนาม เวลา สภาพพื้นที่เป็นข้อความประกอบ
3. กรอกธาตุทั้งหมดคั่นจุลภาค เลือกธาตุที่สนามเติม
4. ตั้งมานาที่เติมต่อธาตุเมื่อเริ่มเทิร์น 0–10 ค่าเริ่มต้น 2 สะสมสูงสุดธาตุละ 10
5. เพิ่ม/แก้/ลบช่วง ตั้งชื่อ และผูก Rules ก่อนออกจากช่วง
6. เพิ่มแอคชั่น ชื่อ ชนิด Attack / Def / Skill / Item, ช่วง และค่าใช้จ่ายมานาแต่ละธาตุ
7. เพิ่มผล HP/MP/EN, มานา, ธาตุสนาม หรือสถานะ เลือกตนเอง/อีกฝั่งตามชนิดผล
8. ผล vital เลือกบวกตาม ACT/DEF/SPE/CRI หรือคุณลักษณะโครงการพร้อมตัวคูณได้

เลือกผู้ต่อสู้สองตัวที่ต่างกัน เริ่มต่อสู้ แล้วเริ่มเทิร์นเพื่อรับมานาครั้งเดียว เลือกแอคชั่นในช่วง ระบบตรวจข้อมูลและมานาก่อนใช้ผล แสดงค่าที่เปลี่ยนและบันทึก พร้อมฟินิทเมื่อแอคชั่นเสร็จ กดเปลี่ยนช่วง/จบเทิร์นตามปุ่มเพื่อสลับฝ่าย Rules ของช่วงไม่ผ่านจะค้างช่วงเดิม

หน้าตัวละครแสดงภาพ HP/MP/EN สถานะ มานา ช่องการ์ดและความสามารถ โมดูลที่ผูก Battle เพิ่มผลได้เมื่อชนิด/กฎตรง ดูรายงานหากข้อมูลไม่ครบ บันทึกจุดอ่านเพื่อกลับลำดับเดิมโดยไม่เติมมานาซ้ำตอนโหลด

ข้อความฉากไม่ใช่สูตรที่ตีความเอง แอคชั่น Item ใน Battle ใช้ผลที่ตั้งใน Battle ไม่ได้เรียก Effects ของทะเบียนไอเทมทุกชนิดโดยอัตโนมัติ

## รูปแบบ และคำสั่งของแอป
<!-- menu: commands -->

**รูปแบบ:** แตะช่องเนื้อหาที่รองรับ เลือกข้อความ แล้วเปิดเครื่องมือเพื่อทำตัวหนา เปลี่ยนขนาด/สี หรือแทรกลิงก์ไปเรื่อง กฎ การ์ด บอร์ด สถานที่ ไอเทม ปลายทางต้องยังอยู่ ช่องโค้ด/เงื่อนไขไม่ใช้รูปแบบนี้

**คำสั่งและคู่มือ → คำสั่ง:** เลือกแล้วกดทำคำสั่ง ดูผลด้านล่าง:
- สรุปจำนวนข้อมูล: นับเรื่อง การ์ด ตัวละคร บอร์ด สถานที่ ไอเทม อีเวนต์ ชุดกฎ
- เพิ่มรายการในหน้าปัจจุบัน: ส่งคำสั่งเพิ่มชนิดที่หน้านั้นรองรับ
- บันทึกโครงการ: เก็บลงเครื่องและรายงานผล
- ส่งออกสำเนา JSON: เลือกตำแหน่งและยืนยันบันทึกไฟล์

ชุดนี้ทำงานกับโครงการที่เปิด ไม่ได้เชื่อม npm หรือเครื่องมือ W3 ภายนอก แท็บคู่มือใช้เนื้อหาเดียวกับปุ่ม ? ด้านบน

## อัปเดตแอปและคู่มือ
<!-- menu: update -->

1. ต่ออินเทอร์เน็ต เปิดโครงการ กด **↑ อัปเดต**
2. ตรวจ GitHub Release ล่าสุดเทียบรุ่นติดตั้ง ไม่มีรุ่นใหม่จะแจ้งผล
3. หากมี อ่านข้อความรุ่น ดาวน์โหลด และให้ Android ยืนยันติดตั้ง ใช้กุญแจเดิมจึงอัปเดตทับได้
4. เปิดคู่มือหลังติดตั้ง เทียบรุ่นหัวคู่มือกับเลขใต้ชื่อแอป
5. สำรอง JSON เป็นระยะ โดยเฉพาะก่อนย้ายเครื่องหรือติดตั้งคนละกุญแจ/แพ็กเกจ

คู่มือบรรจุใน APK เปลี่ยนพร้อมรุ่นแอปและอ่านออฟไลน์ ปุ่มอัปเดตไม่เขียนคู่มือใน APK เก่าหรือสร้างคำอธิบายเอง ผู้พัฒนาต้องทบทวนรายละเอียดก่อนออกแต่ละรุ่น

ขั้นสร้างมี **check:manual** ตรวจเลขรุ่น หัวข้อเมนู และข้อมูลตรวจทาน **verify:release** ตรวจว่าคู่มือและข้อมูลรุ่นใน assets ตรงต้นฉบับ หากไม่ผ่านต้องแก้ก่อนเผยแพร่ ผู้พัฒนายังต้องอ่านทบทวนเมื่อเพิ่มฟังก์ชัน การตรวจอัตโนมัติรับรองทุกประโยคไม่ได้

## ข้อมูล ออฟไลน์ และแก้ปัญหา
<!-- menu: storage -->

- ข้อมูลอยู่ในพื้นที่แอป/เบราว์เซอร์ของเครื่อง การล้างข้อมูล/ถอนแอปอาจทำให้ข้อมูลหาย ให้เก็บ JSON นอกแอป
- APK มีเว็บและตัวอ่าน Markdown ในตัว ใช้แก้/อ่านออฟไลน์ อัปเดตและลิงก์ภายนอกต้องมีเครือข่าย
- บันทึกไม่ผ่าน: เก็บหน้าที่เปิด ส่งออกสำเนา ตรวจพื้นที่ว่าง ลดขนาดรูป
- ข้อมูลไม่อยู่ในอีกแอป: Chrome กับ APK แยกพื้นที่ ให้นำเข้า JSON
- กฎ UNKNOWN: ตรวจ input ข้อมูลเข้า และคำสั่งที่ยังไม่มีตัวประมวลผล
- Event ERROR: ตรวจ trigger, condition และ action ว่ารองรับ
- ตารางไม่เห็นข้อมูล: ตรวจบอร์ด ขนาด คำค้น และมุมมอง
- ธีมอีกบอร์ดไม่เหมือนกัน: ธีมตารางเก็บแยกบอร์ด ให้ตั้งในบอร์ดที่ต้องการ
- คู่มือไม่ตรงรุ่น: เทียบเลขหัวคู่มือกับรุ่นแอปแล้วตรวจอัปเดต อย่าเทียบกับเวอร์ชันโครงการ

รูปอ้างอิง @ check id, from/in และชื่อ MEP-1 / SEP_1.0 เป็นแนวทางที่เคยหารือ ยังไม่ใช่ไวยากรณ์ที่แอปรันได้ทั่วไป ใช้ ID และตัวประมวลผลที่ระบุเป็นหลัก
