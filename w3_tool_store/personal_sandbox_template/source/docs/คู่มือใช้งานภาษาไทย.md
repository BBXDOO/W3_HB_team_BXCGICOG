# คู่มือ W3 Personal Sandbox (ฉบับงานระหว่างพัฒนา)

คู่มือนี้อธิบายสิ่งที่รุ่นปัจจุบันทำได้จริง ระบบเก็บข้อมูลในเครื่องที่เปิดแอป Android ติดตั้งแยกได้ ข้อมูลใน Chrome กับใน APK แยกกัน ให้นำไฟล์ JSON เข้าแอปหากต้องการย้ายโครงการ

## เครื่องมือใหม่ในรุ่น v38

ปุ่มหุ่นยนต์ทางซ้ายเปิด **จัดรูปแบบเนื้อหา**: แตะช่องเนื้อหาที่รองรับ เลือกข้อความ แล้วเปิดปุ่มหุ่นยนต์เพื่อทำตัวหนา เปลี่ยนขนาดหรือสีตัวอักษร หรือแทรกลิงก์ไปยังเรื่อง กฎ การ์ด บอร์ด สถานที่ หรือไอเทมในโครงการเดียวกัน เนื้อหาเก็บเป็นข้อความพร้อมเครื่องหมายรูปแบบและแสดงผลในพรีวิว ไม่ใช้กับช่องโค้ด/เงื่อนไขที่ระบบประมวลผล ปลายทางลิงก์ต้องยังมีอยู่

ปุ่มสมองในแถบล่างเปิด **คำสั่งและคู่มือ** เลือกสรุปจำนวนรายการ เพิ่มรายการในหน้าปัจจุบัน บันทึกโครงการ หรือส่งออก JSON ได้ และเปิดคู่มือในแท็บเดียวกัน คำสั่ง npm หรือเครื่องมือใน W3 ยังไม่ได้เชื่อมต่อ

ปุ่ม 🎨 ด้านบนเลือกสีให้เมนูและรายการ ส่วนรูปจากเครื่องจะแสดงเป็นพื้นพื้นที่ทำงานด้านหน้าและบันทึกในโครงการ ภาพใหม่ถูกย่อสูงสุด 2048 พิกเซลเพื่อรักษาความคมและควบคุมพื้นที่เก็บข้อมูล หากภาพใหญ่เกินพื้นที่เก็บ แอปจะแจ้งให้เลือกรูปเล็กลง

## 1. โครงการและพื้นที่เก็บข้อมูล

ที่หน้าแรก กดสร้างโครงการ ตั้งชื่อ แล้วเลือก Library, BG–Bookcraft หรือ Concept mind map ข้อมูลของแต่ละโครงการแยกกัน โหมดเป็นชุดเมนูเริ่มต้นใน Playtest; ไม่ได้ห้ามนำบอร์ดหรือการ์ดไปใช้ในโหมดอื่น

เปิดโครงการเพื่อแก้ไข กดบันทึกหรือส่งออก JSON เพื่อสำรองข้อมูลต้นฉบับ นำเข้า JSON จากหน้าแรกได้ ก่อนส่งออกให้กด **บันทึกจุดอ่าน** ใน Playtest ไฟล์ JSON รุ่นใหม่รวมจุดเล่นล่าสุดที่บันทึกไว้กับข้อมูลโครงการ แต่การเปลี่ยนแปลงใน Playtest ที่ยังไม่กดบันทึกจะไม่อยู่ในไฟล์ เมื่อ Import หากมีโครงการรหัสเดียวกันอยู่แล้ว ระบบจะถามก่อนแทนที่ทั้งโครงการและจุดเล่น ไฟล์ JSON รุ่นเก่าที่ไม่มีจุดเล่นยังนำเข้าได้

## 2. Story และตัวเลือก

สร้างหัวข้อเรื่องแล้วเพิ่มตัวเลือกที่ชี้ไปยังหัวข้อปลายทางด้วยรหัสโหนด Playtest กดตัวเลือกเพื่อเปิดหัวข้อนั้น หากรหัสปลายทางไม่มี ระบบจะแจ้งว่าไม่พบปลายทาง ตัวเลือกยังไม่ใช่เงื่อนไขที่รันอัตโนมัติ

## 3. Board, Location และตำแหน่ง

Board กำหนดชื่อ ความกว้าง/สูง และข้อมูลแต่ละช่องโดยพิกัด x,y; Location เป็นระเบียนอีกชนิดหนึ่ง ช่องของ Board สามารถอ้าง Location ด้วยรหัสและอ้าง Event ได้ พิกัดในตารางนี้ไม่ใช่ GPS

Playtest แตะช่องเพื่อ **ดู** รายละเอียด (กรอบสีฟ้า) เลือกตัวละครแล้วกดวาง/ย้ายเพื่อบันทึก **ตำแหน่งที่อยู่** (จุดเขียวกระพริบ) ทั้งสองสถานะไม่ใช่สิ่งเดียวกัน ตำแหน่งบันทึกด้วยปุ่มบันทึกจุดอ่าน; ยังไม่มีการเดินตามกฎ ระยะทาง หรือการต่อสู้

## 4. Characters และ Cards/Modules

ตัวละครมีชื่อ บทบาท ประวัติ ภาพ HP/MP/EN ค่าความสามารถที่เพิ่มใน schema ของโครงการ และช่อง A/B/C ที่เลือกการ์ดได้ ใช้บทบาทนิยามผู้เล่น NPC หรือ monster ได้ แต่ Playtest ยังไม่มีระบบพฤติกรรมแยกตามประเภท

หน้าการ์ดแยกแท็บ **การ์ด** กับ **โมดูล** โมดูลเป็นข้อมูลอีกชุดหนึ่งในโครงการ มีชื่อ ประเภท Grade และข้อความ A/B/C การ์ดมี Grade, Access, Rarity และช่องประกอบ 2 หรือ 3 ช่อง เลือกโมดูลจากคลังของโครงการ ถอดหรือเปลี่ยนได้ ข้อความ A/B/C เดิมของการ์ดยังคงอยู่เพื่ออ่านข้อมูลเก่า

Playtest กด **ลองเดินโฟลว A → B → C** ที่การ์ด ระบบไล่แต่ละโมดูลตามลำดับช่อง แล้วอ่านข้อความ A, B, C ที่ไม่ว่าง คำสั่งพื้นฐาน `PASS` ใช้ผ่านขั้นตอน และ `DISPLAY: ข้อความ` ใช้แสดงผลข้อความ โดยไม่เปลี่ยนข้อมูลหรือค่าสถานะ ถ้าข้อความอื่นยังไม่มีตัวประมวลผล จะขึ้น `UNKNOWN` พร้อมระบุจุดที่ติด ถ้าโมดูลที่อ้างถึงหายหรือ `DISPLAY:` ไม่มีข้อความ จะขึ้น `ERROR` ระบบยังไม่ตรวจ Grade/Access และไม่ตีความโค้ดทั่วไปเป็นคำสั่งอัตโนมัติ โครงการอื่นสามารถเพิ่มชนิดคำสั่งในตัวประมวลผลภายหลังได้

หน้า Rules: ข้อชนิดเงื่อนไขระบุชื่อ input เช่น `area.type` หรือ `character.INT`, เครื่องหมายเปรียบเทียบ และค่าที่ต้องการได้ ทดลองใส่บริบทเป็น JSON object เช่น `{"area":{"type":"เมือง"},"character":{"INT":4}}` แล้วกด **ตรวจเงื่อนไข** ระบบรายงาน PASS/FAIL/UNKNOWN/ERROR ตามแต่ละข้อ ข้อคำอธิบายและ Markdown ไม่ถูกประมวลผล การอ้างอิงคำสั่ง Common Play ยังเป็นข้อมูลสำหรับการเชื่อมต่อในอนาคต ไม่เรียกคำสั่งจริงหรือเปลี่ยนสถานะ การทดลองไม่บันทึกบริบทเข้าโครงการ และข้อย่อยในขณะนี้ตรวจแยกกัน ไม่สืบทอดเงื่อนไขของข้อแม่

ใน Playtest เลือกรายการ **Rules** แล้วกด **ตรวจ Rules กับบริบทปัจจุบัน** เพื่อประเมินกฎจากข้อมูลโครงการและสถานะที่กำลังแสดง เช่น `board.width`, `cell.x`, `location.type`, `character.INT`, `character.hp`, `story.title` ข้อมูลตัวละครใช้ค่า HP/MP/EN ล่าสุดของรอบเล่นถ้ามี เลือกไอเทม การ์ด อีเวนต์ หรือสถานที่ก่อนสลับมา Rules เพื่อเพิ่มรายการที่แตะล่าสุดในบริบท เปิด “ข้อมูลที่ส่งเข้ากฎ” เพื่อตรวจค่าจริงได้ ชื่อที่ไม่อยู่ในบริบทจะได้ UNKNOWN การตรวจยังไม่ทำให้ค่าเปลี่ยนหรือเรียก Common Play; กฎไม่รันอัตโนมัติเมื่อเดินบนบอร์ด

หน้า **Common Play** แยกจาก Rules ใช้เพิ่มรายการคำสั่งเฉพาะโครงการ แต่ละรายการมี ID ที่ไม่เปลี่ยนตามชื่อ ชื่อแสดง คำอธิบาย และรายชื่อ input ที่ต้องมี (คั่นด้วยจุลภาค; กดออกจากช่องเพื่อบันทึก) คัด ID ไปใส่ช่องอ้างอิงคำสั่งของข้อกฎได้ หากเงื่อนไขผ่านและอ้าง ID ที่ไม่มีอยู่จะได้ ERROR หากมีรายการแต่ยังไม่มีตัวประมวลผลจะได้ UNKNOWN รวมถึงกรณี input ที่ต้องมีขาดหาย คำอธิบายใน Common Play ยังไม่ใช่โค้ดและไม่ถูกสั่งรัน รายการของแต่ละโครงการแยกกันและรวมอยู่ในไฟล์สำรองโครงการ

หน้า Items เป็นทะเบียนไอเทมของโครงการ ใน Playtest เปิดรายการ Items แล้วกด **หยิบ +1** เพื่อนำไอเทมที่ลงทะเบียนเข้าช่องเก็บของของตัวละครที่เลือก หรือของโครงการหากไม่มีตัวละคร กด **นำออก −1** เพื่อลดจำนวน ระบบปฏิเสธ ID ที่ไม่อยู่ในทะเบียน จำนวนติดลบ และจำนวนเกินข้อกำหนด stackable/maxStack ที่ตั้งไว้ กด **บันทึกจุดอ่าน** เพื่อเก็บจำนวน และ **เปิดจุดอ่าน** เพื่อเรียกกลับ การสำรองโครงการรวมจุดอ่านที่บันทึกแล้วด้วย ยังไม่มีคำสั่งใช้เอฟเฟกต์ไอเทมหรือแจกไอเทมอัตโนมัติจากพื้นที่/อีเวนต์

### ข้อตกลงรูปอ้างอิงสำหรับขั้นต่อไป (ยังไม่ใช่คำสั่งที่แอปรันได้)

ผู้ใช้เสนอให้เรียกโครงสร้างแต่ละหน้าและเมนูด้วยชื่อทับศัพท์แบบสั้น หากชื่อยาว ให้ใช้ตัวแรกและสองตัวท้ายรวมสามตัว พิมพ์เล็ก รูปอ้างอิง `@ check id : charactor/r` เป็นตัวอย่างที่ผู้ใช้ให้ไว้ (รักษาการสะกดตัวอย่างเดิมไว้ก่อน) เมื่อต้องการดึงค่าสถานะของตัวละคร ให้อ้างหน้าและรายการด้วย ID เช่น STR/DEX/INT โดยไม่ใช้ชื่อแสดงเป็นกุญแจถาวร

คำเชื่อม `from` หมายถึง **อ้างจากหน้ารายการ** ส่วน `in` หมายถึง **อยู่ในขอบเขตพื้นที่** จึงไม่ควรใช้แทนกัน ตัวอย่างเชิงความหมาย: `from` หน้าไอเทมที่ลงทะเบียนแล้ว, `in` พื้นที่หรือช่องบนบอร์ด ยังไม่ได้กำหนดไวยากรณ์เต็มของคำสั่งเหล่านี้

รูปการจัดเรื่องที่ผู้ใช้กำหนดคือ `MEP-1` สำหรับเรื่องหลัก (M = main) และ `SEP_1.0` สำหรับเรื่องย่อย (S = sub) โดยรักษาตัวพิมพ์ใหญ่ของรหัสชุดนี้ตามตัวอย่าง รหัสเหล่านี้เป็นแนวทางชื่ออ้างอิง ไม่ใช่ ID ภายในที่สร้างอัตโนมัติในรุ่นปัจจุบัน การสร้างรหัส การกันรหัสซ้ำ การเชื่อม inventory และการอ่าน `@ check id`/`from`/`in` ยังต้องพัฒนาและทดสอบก่อนใช้งานจริง

## 5. Rules และ Events

Rules มีชุดกฎหลายชุด แต่ละชุดมีข้อหลักและข้อย่อยแบบทรี กด + เพื่อเพิ่มข้อและเขียน Markdown เป็นข้อความ/อ้างอิงได้ เลขข้อเป็นลำดับสำหรับอ่าน แยกประเภท “คำอธิบาย/อ้างอิง” และ “เงื่อนไขที่นิยามไว้” ทั้งคู่ยังไม่ถูกประมวลผลอัตโนมัติ

Events เป็นคนละระบบกับ Rules ตั้งชื่อ กำหนด trigger, condition, cooldown, จุดบน Board และขั้นตอนผลลัพธ์ได้ Playtest รองรับการกดโต้ตอบกับ OnInteract ที่ cooldown 0, ตรวจ HP/MP/EN ด้วยตัวเลข, แสดง Message ไปยัง Self และปรับค่า HP/MP/EN ตามรูปแบบที่หน้ากรอกระบุ คำสั่งอื่นหยุดโดยไม่ใช้ผลบางส่วน พรีวิวในหน้าแก้ไขไม่ใช่การรันจริง

## 6. เครื่องมือ Playtest และเมนู

Playtest อ่านข้อมูลตามรายการด้านซ้าย ชื่อ ไอคอน ลำดับ และรายการที่แสดงปรับได้เฉพาะโครงการนั้น เครื่องมือลูกเต๋ารองรับ 1–10 ลูก ชนิด d4/d6/d8/d10/d12/d20/d100 ประวัติผลทอย 20 รายการล่าสุดเก็บเมื่อกดบันทึกจุดอ่าน

หน้าต่างรายละเอียดของช่องบอร์ดแสดง Location และ Events ที่อ้างถึง กดโต้ตอบ Event ได้ ส่วนเมนูพื้นที่หลายชั้น เช่น ประเทศ → จังหวัด → หมู่บ้าน และชุดคำสั่งจำลองการค้า/ประชากร ยังไม่ได้สร้าง กำหนดความหมายและความสัมพันธ์ใน Rules ก่อน แล้วค่อยเชื่อมกับเมนูใช้งาน

## 7. ขอบเขตการเก็บและออฟไลน์

โครงการอยู่ในพื้นที่เก็บข้อมูลของแอปบนเครื่องนั้น การล้างข้อมูลแอปอาจลบข้อมูลได้ การสำรองด้วย JSON จำเป็นเมื่อใช้ข้อมูลสำคัญ APK เปิดได้แบบออฟไลน์

## 8. เขียน Story เต็มจอ และเอกสาร Markdown

1. เปิดโครงการ → Story → **รายการ / เพิ่ม** แล้วแตะชื่อตอน หรือกด **เขียนตอนใหม่** เพื่อเปิดหน้าต่างเขียนเต็มจอ
2. ตั้งชื่อและเขียนในช่องต้นฉบับ เลือก **เขียน**, **เขียน + พรีวิว** หรือ **พรีวิว** ได้ แถบคำสั่งทั้งสองแถวปัดซ้าย–ขวาเพื่อดูปุ่มที่เหลือได้
3. ตอนใหม่ใช้ **Markdown / GitHub** ตอนเก่าเก็บรูปแบบเดิมไว้ก่อน เลือกเปลี่ยนรูปแบบเองได้ รองรับหัวข้อ ตัวหนา/เอียง/ขีดฆ่า ตาราง รายการ เช็กลิสต์ ลิงก์ บล็อกโค้ด และ `<details><summary>หัวข้อ</summary>…</details>` สำหรับพับอ่าน
4. **นำเข้าไฟล์** รองรับ `.md`, `.markdown`, `.txt` แบบ UTF-8 ไม่เกิน 4 MB เลือกสร้างตอนใหม่ เพิ่มท้ายตอนปัจจุบัน หรือแทนที่เนื้อหา การแทนที่จะถามยืนยันก่อน การเพิ่มท้ายเก็บรูปแบบของตอนเดิมไว้
5. **ส่งออก .md / .txt** ส่งออกต้นฉบับเฉพาะตอนที่เปิดอยู่ บน Android เลือกโฟลเดอร์และยืนยันบันทึกได้ ข้อมูลส่วนอื่นของโครงการสำรองด้วย JSON จากแถบหลักตามเดิม
6. บันทึกอัตโนมัติหลังหยุดแก้ประมาณ 2 วินาที หรือกด **บันทึก** ดูสถานะที่แถบล่าง หากพื้นที่ไม่พอ หน้าต่างจะยังเปิดไว้ให้ส่งออกสำเนาก่อนปิด ปุ่ม **← Story** และปุ่มย้อนกลับของ Android ใช้กลับรายการได้
7. ค้นหา/แทนที่ทำงานกับข้อความตรงตัว ใช้ **↶ / ↷** เลิกทำและทำซ้ำได้ รวมถึงย้อนการนำเข้าแทนที่ในตอนเดียวกัน ปุ่ม **A− / A+** ปรับเฉพาะขนาดที่ใช้เขียนและพรีวิว

ลิงก์เว็บไซต์เปิดเมื่อแตะเท่านั้น ภาพที่อ้างใน Markdown แสดงคำบรรยายแทนในรุ่นนี้ ยังไม่ได้แนบไฟล์ภาพเข้าตอนโดยอัตโนมัติ และ HTML ที่ไม่ปลอดภัยจะไม่ทำงานในพรีวิว เครื่องมือและตัวอ่าน Markdown บรรจุอยู่ในแอปเพื่อใช้งานออฟไลน์
