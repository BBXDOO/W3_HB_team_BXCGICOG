# W3 System Console

แอปคอนโซลทดลองสำหรับดูแผนที่ระบบ เขียนบันทึก และตามหลักฐานของโค้ดจากมือถือ

## เปิดจาก Termux

ใช้ Git และ Python 3.12 ขึ้นไป จากรากรีโป้ W3

```sh
python -m pip install -r w3_tool_store/w3console/requirements.txt
python w3_tool_store/w3console/serve.py
```

เปิด [127.0.0.1:8765](http://127.0.0.1:8765) ในเบราว์เซอร์บนเครื่องเดียวกัน
ระบบอ่านไฟล์ที่อยู่ใน Git revision ที่เลือก ณ เวลาเริ่มแอป ใช้ `--ref` เพื่อเลือกรุ่นอื่น และ `--port` เพื่อเปลี่ยนพอร์ต

- **ไฟล์และตัวเขียน** เปิดโฟลเดอร์หรือค้นตามพาธ อ่านไฟล์ข้อความ UTF-8 ได้ถึง 512 KiB พิมพ์ คัดลอก วาง บันทึกร่าง และส่งออกไฟล์ แถบ Markdown รองรับหัวข้อ ตัวหนา ลิงก์เว็บ ตาราง รายการ และบล็อกโค้ด
- **ฉบับร่าง** เก็บในเบราว์เซอร์ แยกตาม Git revision และพาธ การส่งออกสร้างสำเนาไฟล์ ส่วนต้นฉบับอ้างอิง Git ที่เปิดอยู่
- **ความสัมพันธ์ · CROLL** แสดงสายตรวจที่กำหนดไว้หนึ่งสาย อ่านคำสั่งจาก YAML อ่านจุดเรียกและนิยามด้วย Python AST และอ่าน `$ref` จาก JSON Schema แตะป้ายเพื่อเปิดซอร์สตามบรรทัดหลักฐาน ถ้าจุดอ้างอิงเปลี่ยนจะแจ้งว่ายังยืนยันไม่ได้
- ตารางและเมนูของ System Console เดิมยังใช้งานสำหรับโหนดที่สร้างเอง ทั้งสองส่วนใช้ข้อมูลคนละชุดในรอบทดลองนี้

## สร้างผลทดสอบ CROLL

จากรากรีโป้เดียวกัน รันกับ revision ที่เชื่อถือได้

```sh
python w3_tool_store/w3console/verify.py
```

คำสั่งนี้ส่งไฟล์จาก Git เข้า `copy_source` ของ Agent Workbench เพื่อจัดสำเนาแยก แล้วรันชุดตรวจ CROLL สองชุดในรายการ Workbench ด้วย unittest ผลอยู่ใน `w3_tool_store/w3console/.local/run.json` และแสดงเมื่อเปิดแท็บความสัมพันธ์ด้วย commit เดียวกัน หากใช้ `--ref` ให้ระบุค่าเดียวกันกับตอนเปิดแอป

workflow ในแผนผังเรียกชุดทดสอบ **Workbench** บน GitHub Actions ส่วนผลรันที่คอนโซลแสดงมาจากการทดสอบ **CROLL บนเครื่อง** ซึ่งใช้ข้อมูลทดสอบ สายนี้แสดงการตรวจสัญญาและความสัมพันธ์ของไฟล์ การตามงาน production ยังต้องมีหลักฐานจากการรันจริง

แอปรอบนี้เปิดผ่านเบราว์เซอร์ในเครื่อง โค้ดวิเคราะห์รองรับสาย CROLL ที่ระบุไว้ ส่วนไฟล์ข้อความภาษาอื่นเปิดอ่านและเขียนร่างได้ตามปกติ
