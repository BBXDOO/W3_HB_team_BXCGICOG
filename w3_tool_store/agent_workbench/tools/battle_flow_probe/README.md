## งานที่ทดลอง

- สนามเติมมานาธาตุที่ยังใช้งาน ธาตุละ 2 เมื่อเริ่มเทิร์นของฝั่งนั้น สูงสุดธาตุละ 10 และไม่เติมซ้ำเมื่อเรียกเริ่มเทิร์นอีกครั้ง
- การ์ดที่ติดตั้งให้สิทธิ์เลือกแอคชั่นในเฟสที่กำหนด ค่าร่ายทุกธาตุต้องพอก่อนจึงหักและเกิดผล
- แอคชั่นใช้ผล HP หรือเปิด/ตัดธาตุสนาม ข้อมูลสนามเปลี่ยนแล้วการเติมเทิร์นต่อไปอ่านข้อมูลล่าสุด; มานาที่สะสมไม่หาย
- เดินเฟสตามรายการที่กำหนด; เมื่อหมดรายการจึงสลับฝั่งและรอเริ่มเทิร์นถัดไป
- แอคชั่นสำเร็จคืน `ฟินิท · แอคชั่นเสร็จ` พร้อมบันทึกก่อนและหลัง การไม่ผ่านคืนสาเหตุและไม่เปลี่ยนสถานะ
- ไม่สมมุติตารางธาตุแพ้ทาง สูตรโบนัส ตัวตอบโต้ หรือเงื่อนไขชนะ/แพ้

## รันทดสอบ

จากโฟลเดอร์นี้: `node --test battle_flow_probe.test.mjs`

ผลตรวจในพื้นที่ทดลอง 2026-10-27: ผ่าน 2 ชุด ครอบคลุมเติมมานา, เพดาน 10, ค่าร่ายน้ำ/ลมที่ล้มแล้วไม่หักบางส่วน, การ์ดไม่ได้ติดตั้ง, เอฟเฟกต์ไม่รองรับ, ผลสนาม, เฟส, สลับเทิร์น และ serialize/restore โดยไม่ประมวลผลซ้ำ

## ขอบเขต

ตัวทดลองนี้ใช้ Node.js และข้อมูลตัวอย่างในไฟล์ทดสอบ ไม่เชื่อม UI, Rule/Event, storage หรือ APK รุ่นที่ติดตั้ง; จึงยังไม่ใช่ผลทดสอบบนโทรศัพท์ การตั้งเฟสและแอคชั่นยังเป็นข้อมูลในนิยามที่ส่งเข้า engine; Rule/Event ของแอปปัจจุบันยังไม่ได้บังคับเดินเฟสหรือตอบโต้การ์ดอัตโนมัติ
