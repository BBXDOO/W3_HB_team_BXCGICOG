## Body — บทบาทของพื้นที่

`w3_tool_store/agent_workbench/` เป็นพื้นที่สร้างและเก็บเครื่องมือที่เอเจนท์ของ W3 นำไปใช้กับโครงการต่าง ๆ ได้ เริ่มจากงานทดลอง MPCP และ W3Lgu แล้วขยายตามงานที่มีหลักฐานรองรับ

**สถานะปัจจุบัน: tools/ มี REA MCP probe, Battle flow probe และ Android WebView layout probe; profiles/ มี OPPO Android probe สำหรับ local Blueprint + File.void แล้ว ขอบเขตและผลที่ตรวจได้อยู่ใน README ของแต่ละรายการ ยังไม่มีโค้ด REA core ที่คัดลอกมาปรับเป็นเครื่องมือหรือ editor ใหม่** เครื่องมือ MPCP sandbox และ Paper/Condien ที่สร้างแล้วอยู่ในพาธเดิมนอกโฟลเดอร์นี้ อ้างอิงได้จาก M2 ด้านล่าง

### ที่มาและสิ่งที่รักษาไว้

ใช้รูปแบบ README ตาม AMS เพื่ออธิบายพื้นที่ระดับนี้และเชื่อมกลับไปยังต้นทาง รักษาหลัก Core vs Structure: ปรับโครงสร้างเพื่อรองรับกิจกรรม โดยยังตามรอยเจตนาและที่มาได้

BBX19 กำหนดให้เก็บ `w3_tool_store/xrea/` เป็น prototype ต้นทาง แล้วคัดลอกชุดโค้ดที่ต้องใช้มาสร้างเครื่องมือแยกใน Workbench การพัฒนาเครื่องมือที่เกิดจากสำเนาจะทำในพื้นที่ใหม่นี้ ส่วนต้นทางเก็บไว้อ้างอิงและใช้กับโครงการอื่นต่อได้

Workbench เป็นชื่อของพื้นที่และชุดเครื่องมือที่กำลังพัฒนา ไม่ใช่ชื่อใหม่ของ REA และยังไม่ได้รวม REA เข้ากับ MPCP หรือ W3Lgu

### ขอบเขตและเจ้าของงาน

- เครื่องมือที่ใช้ร่วมกันเก็บใน `tools/` ส่วนวิธีเชื่อมกับระบบเฉพาะเก็บใน `profiles/`
- โครงการ ข้อมูล และผลทดลองของแต่ละเอเจนท์เก็บในพื้นที่โครงการของเอเจนท์นั้น ไม่ใช้ต้นแบบหรือเครื่องมือกลางเป็นฐานข้อมูลร่วมโดยปริยาย
- เครื่องมือทำงานตามขอบเขตคำขอและสิทธิ์ที่มี การคัดลอกหรือเรียกใช้เครื่องมือไม่สร้างสิทธิ์แก้ระบบหรืออนุมัติงานเพิ่มเติม
- การจัดตั้งพื้นที่นี้ไม่เปลี่ยนความหมายหรือกติกาของ MPCP, W3Lgu, ROT หรือระบบอื่น เอกสารของแต่ละระบบยังเป็นต้นทางของขอบเขตนั้น
- README นี้อธิบายเฉพาะโฟลเดอร์ Workbench รายละเอียดของพื้นที่ย่อยให้เก็บใน README ของพื้นที่นั้น และเชื่อมด้วยลิงก์

### การนำโค้ดต้นแบบมาสร้างเครื่องมือ

1. กำหนดงานที่จะให้เครื่องมือทำ ข้อมูลเข้า ผลลัพธ์ ขอบเขตผลกระทบ และวิธีตรวจผลก่อนเลือกชุดโค้ด
2. ตรวจโครงสร้างและ dependency ของต้นแบบ แล้วคัดลอกชุดที่ทำงานร่วมกันได้ไปยังโครงการเครื่องมือแยกใน `tools/` ไม่แก้ prototype เพื่อรองรับงานปลายทาง
3. บันทึกต้นทาง พาธ ชื่อผู้พัฒนา เวอร์ชันหรือ commit ที่ตรวจสอบได้ รายการที่คัดลอก และสิ่งที่เปลี่ยนไว้ใน README ของเครื่องมือนั้น หากยังไม่ทราบเวอร์ชัน ให้ระบุว่าไม่ทราบ
4. เก็บ license และ copyright notice ของโค้ดที่นำมาใช้ไว้กับสำเนาตามเงื่อนไขต้นทาง ไม่แทนที่ชื่อผู้พัฒนาต้นฉบับด้วยชื่อเจ้าของพื้นที่ W3
5. ทดสอบกับงานจริง เก็บหลักฐานผลและข้อจำกัด แล้วจึงระบุว่าความสามารถใดใช้งานได้ ไม่มีการถือว่าโค้ดที่คัดลอกมาพร้อมใช้เพียงเพราะมีชื่ออยู่ในทะเบียน

### วงจรการพัฒนาที่ตั้งใจรองรับ

รับโครงการ → ตรวจโครงสร้างและส่วนที่ขาด → ทดลองในพื้นที่แยก → เก็บหลักฐาน → ปรับในขอบเขตสิทธิ์ → ตรวจซ้ำ → ส่งผลหรือรอการตัดสินใจ

วงจรนี้เป็นเป้าหมายของ Workbench ยังไม่ใช่ความสามารถอัตโนมัติที่สร้างครบแล้ว จุดเริ่มต้นที่มีอยู่คือ MPCP sandbox สำหรับ local setup ซึ่งสร้าง partition และ manifest พร้อมหลักฐานได้ แต่ยังไม่ได้เป็นเครื่องมือที่เกิดจากการคัดลอก xrea
