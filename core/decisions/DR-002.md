# DR-002 — Adoption of Formal Cross-Module Decision Request Process

## Decision Record

- **Decision ID:** DR-002
- **Date:** 2026-05-02
- **Status:** APPROVED
- **Authority:** BBX19
- **Impact:** HIGH

## เรื่อง (Subject)
Adopt formal GitHub issue template-based Decision Request process as the official governance mechanism for all cross-module decisions in W3.

## วันที่ (Date)
2026-05-02

## เหตุผล (Rationale)
1. All 6 modules are active and operating under Phase 2 governance framework.
2. Cross-module decisions have previously lacked a structured, traceable format.
3. The W3 governance framework (Phase 2) mandates that all critical decisions be logged with decision-maker, rationale, and impact assessment.
4. A standardized request template ensures consistency, traceability, and accountability across all modules.

## ตัวเลือก (Options Considered)

### Option A — Informal ad-hoc decisions
- Description: Each module makes decisions independently and records them in its own format.
- Pros: Flexible, fast.
- Cons: No cross-module consistency; decisions are difficult to audit; governance gaps emerge over time.

### Option B — Formal Decision Request template (Issue-based)
- Description: All cross-module decisions are submitted via the `.github/ISSUE_TEMPLATE/decision-request.md` template and reviewed by all affected modules before BBX19 final sign-off.
- Pros: Traceable, auditable, consistent; aligns with Phase 2 governance framework; enables cross-module visibility.
- Cons: Slightly slower than informal decisions.

## สิ่งที่เลือก (Decision)
**Option B** — Formal Decision Request template process is adopted as the official governance mechanism for all cross-module decisions.

All future cross-module decisions must:
1. Be submitted via the `[DECISION]` GitHub issue template.
2. Identify all affected modules.
3. List options considered with pros/cons.
4. Include an impact analysis and risk level.
5. Obtain BBX19 final sign-off before implementation.

## ผลที่ยอมรับ (Accepted Outcomes)
- Improved governance traceability across all modules.
- Consistent decision format for audit and review.
- Clear accountability: every decision is linked to a requester, reviewers, and an approver.
- All future decisions logged in `core/governance/decisions.md` using Decision ID (DR-XXX).
