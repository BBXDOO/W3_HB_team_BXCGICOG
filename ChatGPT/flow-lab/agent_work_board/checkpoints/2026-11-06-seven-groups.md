# จุดต่อเพิ่มเติม — 7 กลุ่ม สี และคำถามตามรอย
วันที่: 2026-11-06 (Asia/Bangkok)
สถานะ: ข้อกำหนดจาก BBX19 / แบบย่อชื่อเป็นข้อเสนอประยุกต์ ยังไม่สร้าง runtime หรือบอร์ด

## 7 โหนดภาพรวม
| รหัสเสนอ | กลุ่มที่ผู้ใช้ระบุ | หน้าที่บนบอร์ด |
|---|---|---|
| SYS | โครงสร้าง / ระบบ W3 | ระบบและส่วนประกอบของระบบ |
| UNT | หน่วยงาน / หน่วยงานเฉพาะทาง | modules และผู้ปฏิบัติงานอื่นตามหลักฐาน |
| TOL | tools | เครื่องมือและจุดเรียกใช้ |
| DOC | docs | ลิงก์อธิบายเหตุผล เจตนา กฎ และบริบท |
| STO | store | ที่เก็บโค้ด ข้อมูล งาน และหลักฐาน โดยระบุบทบาทจริงแยกกัน |
| GOV | governance | กติกาและกลไกกำกับที่เกี่ยวข้อง |
| PLT | platform / GitHub workflow | โฮสต์ ตัวกระตุ้น และ workflow ของแพลตฟอร์ม |

7 กลุ่มเป็นภาพรวมที่เปิดดูโครงสร้างภายในได้ ไม่ใช่ execution stages และไม่จำเป็นต้องเกิดครบทุกกลุ่มในงานหนึ่งรอบ สิ่งเดียวอาจมีหลายบทบาท/หลายกลุ่มได้ รหัสเหล่านี้เป็นชื่อย่อของบอร์ด ไม่แก้ชื่อหรือ identity เจ้าของระบบ ไม่แทนที่ 14 Root Spaces หรือ 6 Gradation และยังไม่กำหนด mapping อัตโนมัติระหว่างชุดเหล่านี้

DOC ปรากฏในภาพรวมเพื่อค้นหาและเชื่อมบริบท แต่ไม่ถูกเพิ่มเป็นขั้น execution เพียงเพราะเป็นเอกสาร หากโค้ดอ่านไฟล์เอกสารจริง ให้แสดงแอคชั่นอ่านข้อมูลพร้อมโค้ดผู้เรียก ไม่ยกระดับเอกสารเป็นผู้ execute เอง ภาพสมุดเป็นตัวอย่างสำรวจ ไม่ยืนยันความสามารถ runtime ของชื่อที่จดไว้

## ชุดคำถามสร้างเส้นทาง
1. เจตนาที่รับมาต้องการอะไร และมีต้นทาง/รหัสงานอะไร?
2. มีโค้ดหรือองค์ประกอบใดเกี่ยวข้อง อยู่ในกลุ่มใด และยืนยันจากที่ไหน?
3. มีผลลัพธ์คาดหวังหรือไม่ ถ้าไม่ระบุให้บอกตรง ๆ ไม่แต่งแทน?
4. จุดเชื่อมใดรับ input ส่ง output หรือเปลี่ยนรูป ผ่านเงื่อนไข/ตัวเลือกใด?
5. เส้นนั้นเป็นความสัมพันธ์ใน source, แผนเส้นทาง, การเรียกจริง หรือหลักฐานรับส่งของรอบใด?
6. ถ้าตัน มีทางอื่นที่โค้ด/registry รองรับอยู่จริงหรือไม่? หากมีแต่แนวคิดให้ระบุ proposed; หากไม่มีให้บอกว่าไม่มี ไม่สร้าง fallback สมมุติเป็นของจริง
7. เทียบผลจริงกับผลคาดหวังได้หรือไม่? หลักฐานขาดตรงไหน และจะตรวจต่ออย่างไร?

## มี / ไม่มี / ยังไม่ทราบ
- FOUND: พบองค์ประกอบหรือพฤติกรรมใน source ที่ตรวจแล้ว พร้อม commit/path/symbol และหลักฐานตามประเภท
- NOT_FOUND_IN_SCOPE: ไม่พบในขอบเขตที่ระบุ ต้องบอกพื้นที่และวิธีค้น ไม่อ้างว่าไม่มีทั้งรีโป้
- NOT_IMPLEMENTED_CONFIRMED: ยืนยันส่วนที่ยังไม่ implement ตาม code/stub/ข้อจำกัดที่ตรวจได้ ระบุที่มาและขอบเขต
- NOT_INSPECTED หรือ UNKNOWN: ยังไม่ตรวจ/หลักฐานไม่พอ ไม่ใช้แทน failure
- PROPOSED: ความสามารถหรือเส้นทางที่เสนอเพิ่ม แยกจากสิ่งที่มี

คำขอผู้ใช้คือใช้โค้ดที่มีจริง ไม่สร้างความครบจากเอกสารหรือชื่อระบบ สิ่งที่ขาดให้เห็นตรง ๆ เพื่อเลือกงานพัฒนาต่อ

## การใช้สีและสัญลักษณ์
อ่านเอกสารทั้งสามไฟล์แล้ว แต่รอบนี้ยังไม่ตรวจ implementation สีหรือรัน W3DB:
- protocol/mpcp/COLOR_SYMBOL_PAPER.md — Visual Layer v1; SHA acb35ca80ffe4703d99610f4e5280651e30d8920
- protocol/mpcp/COLOR_STATE.md — specification v1.0; SHA 42d1d56bd18acf80756331bc1aa98b24bf5dd234
- docs/w3db_setup.md — คู่มือ ไม่ใช่ผลยืนยัน runtime ปัจจุบัน; SHA 9a4dd58de5aa0369a47b949ca205104a38742f39

ความหมายต่างกันตามชุด:
- COLOR_SYMBOL: Blue = information/reference/external; หนึ่ง primary color และหนึ่ง primary symbol ต่อ item
- COLOR_STATE: Blue = ยังไม่จบ/รอข้อมูล/ห้ามสรุป; รองรับ composite ไม่เกินสองสี ซ้ายไปขวา; Flag แยกจาก State
- W3DB PRX ในคู่มือ: RED ▲ = FORCE/SYSTEM, YELLOW ● = UNCERTAIN/HUMAN, GREEN ■ = STABLE/RESULT, BLUE ◆ = EXTERNAL/in-between; PRX เป็น derived visual output ไม่ใช่ decision node และ state 0/0.5/1 เป็น observation

แนวประยุกต์: แต่ละเครื่องหมายระบุเจ้าของชุดความหมาย ขอบเขต ฟิลด์ต้นทาง และลิงก์คำอธิบาย ไม่รวมชุดสีเป็น mapping เดียว และไม่แปล PRX RED เป็น failure หรือคำสั่ง STOP ของบอร์ด
แยกสีสถานะจากประเภทกลุ่ม/ชนิดความสัมพันธ์ มีข้อความหรือสัญลักษณ์ช่วยอ่าน ไม่ใช้สีอย่างเดียวตัดสินว่ามีครบหรือระบบทำงานแล้ว
ตารางคะแนนใน COLOR_STATE มีช่วงปลายซ้อนกันที่ 50/75/90 จึงไม่สร้าง scoring threshold ใหม่ในรอบนี้ ต้องตรวจโค้ดเจ้าของก่อนนำมาใช้
คำว่า Production Ready ในเอกสารเป็นสถานะเอกสาร ไม่ใช่ผลทดสอบของรอบนี้
